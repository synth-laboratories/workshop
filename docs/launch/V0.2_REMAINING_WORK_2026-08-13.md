### 2.2 Containers journal fixes — must precede the pin

Not started. `44443b4` is **not** a release pin and neither is `6a7313d`. Reproduced defects:

- Concurrent identical `start_rollout` both execute; journal interleaves and `recover()` fails `event_log_sequence_gap` permanently.
- Restart + re-prepare bricks the journal — fails `event_log_record_after_close`, **not** `event_log_sequence_gap`; assert the right one.
- Shared seal `.tmp` → real `FileNotFoundError`; lease leaks with no `try/finally`.
- `http_adapter` idempotency is keyed on the **response** id, not the requested one — every retry re-executes, no concurrency needed.

`prepare()` needs a four-case ladder: fresh → new log; open → recover and continue; **sealed → fail closed 409**; unrecoverable → fail closed with the typed reason, never truncate. Zero concurrency tests exist over these surfaces (the good barrier-based ones all cover `tracing/capture/*`).

Also strike or substantiate two claims in `docs/trace_stream_protocol_v1.md` (`:53-62`, `:184`, `:190`) — the suite proves neither idempotent start nor concurrent isolation, and the one receipt using "concurrent" labels a serial loop.

**New SHA after these fixes is the pin.**
