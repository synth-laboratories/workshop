## Phase A — qualify the complete local experiment workflow

### User outcome

A user can perform this entirely through Workshop:

```text
idea
  -> create experiment
  -> run smallest useful test
  -> inspect traces and receipts
  -> fork a child with one deliberate change
  -> compare parent and child
  -> rerun one node
  -> select a candidate
  -> quit and reopen offline
```

Use a real bounded Craftax coding-agent experiment. Do not use fixture-only
records. Make the hypothesis small and unique so the run cannot be confused
with previous CUA evidence. A valid non-improving result is acceptable.

### Preconditions

1. Build a named v0.8 development candidate from the recorded Workshop commit.
2. Give it a fresh instance root and fresh experiment database/CAS.
3. Start with networking available only for the actual coding model and
   admitted environment operations.
4. Confirm the selected model/provider is visible before starting; record exact
   provider and model identity without exposing credentials.
5. Confirm no prior experiment with the acceptance nonce exists.

### Required journey

1. Open Workshop and create a task from a user-level Craftax improvement idea.
2. Ask the coding agent to state a hypothesis and run the smallest useful
   mechanism test first.
3. Ensure Workshop creates the experiment before execution and pins task,
   candidate, provider/model, config, and request identities.
4. Open the experiment index and locate it by the unique title or digest.
5. Open its lineage view and inspect the baseline/root node.
6. Open retained evidence from the node: logs, trace/trajectory, metrics,
   artifacts, usage/cost source, and terminal receipt where present.
7. Create a child/fork from that node through the admitted Workshop action.
   Make exactly one meaningful change and run it.
8. Compare parent and child without leaving the experiment workspace. Verify
   configuration, result, usage, artifact, and failure differences remain
   honest; unavailable dimensions must not appear as zero.
9. Rerun one node through Workshop. Verify it has a new run identity and a
   typed `rerun_of` edge rather than overwriting the original.
10. Select the candidate to carry forward. Verify the selection/promotion-like
    fact references the exact candidate digest; do not infer from its name.
11. Create or retain at least one bounded failure, such as a rejected preflight
    or intentionally invalid admitted parameter, and confirm it appears as a
    terminal node with an actionable diagnostic.
12. Quit Workshop completely. Deny network access and relaunch the same named
    instance.
13. Reopen the experiment from search. Confirm graph, comparison, traces,
    receipts, selected candidate, failures, and view identity are intact.
14. Export a local portable evidence bundle. Inspect its manifest and prove no
    network request or background upload occurred.

### Phase A invariants

- Root, fork, rerun, failure, evaluation/result, and selection are distinct
  nodes or facts with stable identities.
- Every visible graph edge corresponds to a typed append-only fact.
- Duplicate or delayed events do not create duplicate nodes or regress terminal
  state.
- A rerun never mutates its source node.
- Evidence opens from immutable digest references; the UI does not guess paths.
- Search works by title and at least one exact identity field.
- Unknown cost is null/unknown, never `$0`.
- Closing and reopening the app does not require the coding model or cloud.
- The local SQLite/CAS remains authoritative and no account is required.

### Phase A evidence bundle

Place evidence under a new acceptance-specific directory outside the source
tree until it has been reviewed for secrets. Include:

- acceptance ID and unique nonce;
- Workshop source commit, app identity, signature state, and dirty-state flag;
- monotonic timestamps for each journey checkpoint;
- screenshots or recording of index, DAG, details, comparison, failure, and
  offline reopen;
- experiment, run, candidate, task, artifact, trajectory, and edge identities;
- sanitized event/receipt manifest;
- exported bundle digest and file inventory;
- network-denial and no-upload evidence;
- child-process and port cleanup report;
- defects found, fixes made, tests run, and residual limitations.

### Phase A pass gate

Do not proceed to the paid NanoHorizon run until Phase A passes on the exact
Workshop candidate that will be used for Phase B. If a fix changes the runtime
or renderer commit, rerun the affected Phase A steps and update provenance.

## Phase B — `V08-CUA-NH-001` idea to draft PR

### Fixed user intent

Give the coding agent this intent without implementation instructions:

> Make one small, challenge-legal change intended to reduce NanoHorizon policy
> calls that finish without the required Craftax tool call. Add a focused
> regression test, run the smallest useful experiment first, and prepare a
> reviewable submission PR with the evidence.

The hypothesis does not have to improve the official score. Workflow validity,
honest evidence, and a portable draft PR are the gate.

### Time budget

| Checkpoint | Cold-start ceiling |
| --- | ---: |
| Challenge page to passing credential-free preflight | 15 minutes |
| Idea to tested diff and no-cost mechanism smoke | 15 additional minutes |
| Bounded Modal smoke visible in the local DAG | 15 additional minutes |
| Official-shaped run, MLX verification, bundle, and draft PR | 45 additional minutes |
| Total | 90 minutes |

Only recorded human approval latency is excluded. Setup, queueing, provisioning,
retries, debugging, and automated recovery all count. Record full wall time and
approval-excluded active-system time.

### Preconditions

- Use the Phase A-qualified Workshop candidate in a new fresh named instance.
- Use a fresh dedicated challenge fork pinned to the signed manifest base.
- Git push and draft-PR credentials are already authorized through SSH files,
  project-local `.env`, or Workshop's non-Keychain secrets proxy.
- Modal credentials and signed budget caps are present through an allowed
  mechanism.
- The challenge page, copyable setup prompt, pinned repositories, public seeds,
  baseline, and submission contract all agree on exact digests.
- The Mac meets the declared Apple Silicon/MLX requirements and no unrelated MLX
  or Modal workload occupies the acceptance resources.

If any precondition is absent, record a blocker and fix the product/setup path.
Do not repair the journey manually behind CUA and then continue the clock as if
it succeeded.

### Required CUA journey

1. Start recording and the stopwatch when CUA opens
   `/challenges/nanohorizon` with no prepared local project.
2. Inspect the versioned task, baseline, score, resource limits, submission
   rules, and the three onboarding paths.
3. Copy the page's Workshop setup prompt, open a new Workshop coding task in an
   empty project directory, and paste it.
4. Let the coding agent clone/pin dependencies, create a
   `codex/cua-nanohorizon-*` branch, materialize the starter, and run the
   credential-free preflight. The tester performs no terminal choreography.
5. Give the fixed user intent. Require the agent to explain its hypothesis,
   modify only the admitted submission surface, add a focused test, and show the
   diff.
6. Run local tests and the no-cost mechanism smoke. Any failure must become a
   durable local experiment node with an actionable diagnostic.
7. Request the bounded Modal smoke from Workshop. Verify the approval sheet
   names source/task/config digests, backend, time cap, USD 1.00 maximum, and
   cancellation behavior. Resume only after explicit human approval.
8. Inspect the completed Modal smoke in Workshop. It must show starter -> fork
   -> preflight -> smoke lineage, artifact identity, cost source, trace/tool
   validity, and terminal state.
9. If valid, request the official-shaped bounded run with its exact manifest
   caps and a second explicit approval. Retain failures/retries as nodes.
10. Select the exact candidate and run the local MLX compatibility smoke and
    paired verification. Record adapter conversion with `converted_from` and the
    cross-backend `reproduced_on` verdict. Do not claim bit equivalence.
11. Ask the agent to prepare the submission evidence. It must exclude secrets,
    caches, weights, generated local databases, unrelated changes, and absolute
    host paths.
12. Review `git status`, diff summary, tests, score/limitations, actual observed
    spend, evidence manifest, and proposed PR title/body in Workshop.
13. After explicit approval, let the agent commit, push using the preauthorized
    non-Keychain mechanism, and create a draft PR against the acceptance target.
14. Have CUA open the returned PR URL and verify draft state, base/head commits,
    admitted changed files, evidence references, and initial CI state.
15. Quit Workshop, deny network, relaunch, and reopen the local experiment. DAG,
    receipts, traces, candidate conversion, Git commit, and PR reference must
    remain available.
16. Stop all owned child processes and verify no stale container, trainer,
    sampler, daemon, lease, port, or Modal app remains.

### Phase B hard failures

- Tester uses Terminal, edits files, repairs ports, runs Git, or calls APIs to
  advance the journey.
- Coding agent changes the evaluator, held-out data, task identity, or other
  challenge-owned material.
- Any Keychain access or prompt occurs.
- Paid work starts without the corresponding approval.
- Local experiment data uploads silently.
- A failed/retried run disappears or overwrites another run.
- Cost, score, artifact, or model identity is guessed or duplicated.
- The selected Modal adapter is not the artifact verified on MLX.
- PR includes secrets, weights, cache, local DB, absolute host paths, unrelated
  changes, or targets the wrong base.
- PR is opened as ready-for-review, merged, or submitted to the official
  leaderboard instead of remaining draft.
- Total approval-excluded journey exceeds 90 minutes.
- Cleanup leaves an owned workload running.

## Engineering workflow

For every defect:

1. capture the symptom and the smallest retained reproduction;
2. identify the owning layer rather than patching around it in CUA;
3. add the narrowest regression test;
4. implement the fix without weakening identity, admission, security, or
   accounting checks;
5. run the owning component suite;
6. rebuild the named Workshop candidate if affected;
7. repeat the failed CUA checkpoint and any downstream identity checks;
8. keep the failed attempt in the evidence/DAG.

Commit only scoped changes in the appropriate repository. Do not combine
unrelated dirty work. Record cross-repository dependency commits explicitly.

## Minimum automated verification

Run the owning suites for every changed package, plus at least:

- Workshop Rust experiment/storage/session/recovery tests;
- Workshop experiment presentation and lineage Node tests;
- relevant Workshop Playwright picker, session, and experiment flows;
- NanoHorizon CLI/profile/submission tests;
- portable candidate/task contract parity tests;
- Containers register-then-run and retained-trace tests;
- MLX adapter/conversion/application verification tests;
- formatting/lint/typecheck and `git diff --check` in every changed repo.

Record exact commands and counts in the final handoff. A green suite does not
replace installed CUA evidence.

This assignment is complete only when:

1. Phase A passes from a clean local database through offline reopen and export;
2. the same experiment contracts support the NanoHorizon lineage without a

3. `V08-CUA-NH-001` reaches a valid draft PR in 90 minutes or less;
4. Modal and MLX receipts bind to the same candidate/task identities;
5. all failed and retried attempts remain visible and truthful;
6. no implicit cloud upload, secret leak, guessed cost, or Keychain access is
   observed;
7. all owned resources are terminal;
8. scoped fixes are committed with an integration-ready commit map; and
9. the final report clearly distinguishes PASS, known limitation, and blocker.
