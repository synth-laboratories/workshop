# v0.7 Optimizers runtime — architecture and implementation

Status: locked 2026-08-19  
Parent: [v0.7-scope.md](./v0.7-scope.md)

Users stay in **Optimizers** (page + `optimizer_manage`). Local vs hosted is
recipe placement, not a Training app.

## Locked shape

```text
Workshop OptimizerService
  durable runs, events, visuals, approval, MCP recipes
        |
        v
Optimizers sidecar          ← one local runtime (the plugin)
  admission, capabilities, cancel, event producer
        |
        +-- Search (optimizers)
        |     local  GEPA  → sidecar worker
        |     hosted GELO  → Synth Cloud (admit + reconcile)
        |
        +-- Training
              local  SFT / CISPO → synth-mlx-rl
              hosted SFT / CISPO → public API / Optimizers Beta / Tinker
```

Rules:

- `OptimizerService` never HTTP-calls `:8787`, `:8878`, Tinker, or a
  container for a new training recipe.
- The sidecar advertises **search** vs **training**, and **local** vs
  **hosted** placement.
- MLX is a child of the sidecar (start/health/dispatch), not a peer of
  `OptimizerService`.
- Hosted search/training may run in the cloud; the sidecar still admits
  the recipe and Workshop still mirrors the run.
- The agent only sees `recipe_id` → `optimizer_run_id` → `watch_run` /
  `open_visual`. It never names `synth-mlx-rl`.
- Local `eval.*` stays host-owned (no plugin). Do not fold eval into this
  fan-out in v0.7.
- Hosted OHCO/GELO **product** work remains deferred to v0.8. Hosted GELO
  in the diagram is the existing search/hosted pattern, not a new GELO
  ship.

## Implementation

Land unpushed `synth-mlx-rl` `v0.7/real-backend-only` before Workshop
depends on `cispo_training` or `resume_from_checkpoint`.

### P0 — Contract

Sidecar capability handshake gains:

```text
search.gepa.local
search.gelo.hosted          # existing; no v0.7 GELO feature work
training.sft.local          # mlx
training.sft.hosted
training.cispo.local        # mlx; advertise only when proven
training.cispo.hosted       # fail-closed until canary
```

Workshop `start_recipe` / `start_workflow` for SFT and CISPO go through
the same plugin-ready + pin-run path GEPA uses. Add a host test:
training recipes do not call loopback MLX/SFT URLs from `mlx_sft.rs` /
`sft_client.rs`.

### P1 — Local SFT through the sidecar

1. Sidecar starts/probes `synth-mlx-rl` (loopback, like GEPA worker).
2. Move the job client (preflight, launch, event poll, cancel, resume,
   handoff) out of `mlx_sft.rs` into the sidecar.
3. Map MLX events to `sft.training.metrics`, `sft.checkpoint.ready`,
   `sft.heldout_evaluation.completed` (today heldout becomes
   `mlx.{kind}` and the visual drops it).
4. MCP enum + `use-synth-optimizers` skill: `sft.qwen35-0.8b.mlx.v1`.
5. Optimizers SFT card: **This Mac (MLX · Qwen 0.8B)** vs hosted fixture.

Acceptance: from Workshop, no env-var-only hidden recipe; agent
`start_workflow` creates a local SFT run; visual shows paired heldout;
cancel works; artifacts stay on disk.

### P2 — Local SFT product loop

- Resume via sidecar → `POST /v1/jobs/{id}/resume`.
- Dataset from UI or cookbook, not only `SYNTH_MLX_SFT_*_JSONL`.
- **Chat with this checkpoint** (`policy_snapshot_id` / store digest).
- Honest preflight in the recipe card (service down, not Apple Silicon,
  OOM).

Hardcoded 4-step canary can remain the first bounded recipe; a second
recipe may expose steps inside preflight memory refusal.

### P3 — Hosted SFT through the same admission

Sidecar calls the public SFT service. Workshop stops using
`SftOptimizerClient` as a recipe executor (keep types for mirror if
needed). Same `optimizer.sft.live.v1`. Do not auto-upload MLX adapters
into the hosted LoRA library.

### P4 — Local CISPO through the sidecar

Only after a warm-started MLX CISPO run has a paired heldout receipt.

1. Recipe e.g. `cispo.banking77.mlx.v1`.
2. Sidecar owns MLX + Banking77 loopback container (`training.rollout.*`,
   loopback sampler).
3. Warm-start: SFT adapter on that task, or refuse with
   `cispo_no_learning_signal` explained in the visual — not a crash.
4. CISPO live visual (groups, filtered rollouts, clip, rollout vs update
   time, paired heldout). Do not reuse the GEPA overlay.
5. MCP enum + CISPO card **This Mac**.

### P5 — Hosted CISPO through the same admission

Sidecar owns `HostedTrainingLaunch` (tunnel lease must outlive the run).
Hosted form becomes a bounded recipe, not a free-form agent draft.
Catalog stays fail-closed until a canary with the slime clip identity
(`1 + eps_high`) clears gates. Parallel to P1–P4; not a blocker for
local SFT.

## Agent MCP

Still one server. Add local/hosted SFT and CISPO ids to
`optimizer_start_recipe` / `start_workflow` enums. Skill: SFT/CISPO have

from `gepa` / `go-ex` search. PPO stays out of the local/hosted picker.
