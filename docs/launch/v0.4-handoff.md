## 4. CUA plan

Test ids are stable and unchanged for every destination: `open-visuals`,
`open-reports`, `open-optimizers`, `open-inventory`. The section itself is
`plugins-nav`. `research-nav` and `inventory-nav` are gone by design.

### 4.1 The Plugins section — the core of the change

1. Exactly one section titled **Plugins**. No `Research` heading. No second
   `Data` section heading.
2. Four rows in order: **Visuals, Reports, Optimizers, Data**.
   - The last row reads `Data`, not `Containers · Traces · Usage`.
   - Each row has a **distinct** icon. Before this branch Visuals reused the
     Search glyph and Reports and Optimizers shared one. If any two look alike,
     that is a bug.
3. Each row opens its existing page, and the active row is styled as selected.
4. Collapse and expand the section by keyboard. `aria-expanded` must track, and
   focus order must survive the collapse.
5. Section state is intentionally **not** persisted across restarts.

### 4.2 Optimizers lifecycle status — the row must never vanish

The Optimizers row previously disappeared when the plugin was disabled. It must
now stay, state its phase, and still open its page. Status text appears at
`plugin-status-optimizers`.

| State | Row should read | Row should still |
|---|---|---|
| ready | `Ready`, subdued | open the workspace |
| disabled, no runs | `Disabled` | open the page |
| disabled, N runs live | `Disabled · N running` | open the page |
| not installed | `Not installed` | open the page |
| stopped / degraded | `Needs attention` | open the page |
| error | `Error` | open the page |
| transitional | phase name plus a spinner | open the page |
| plugin bridge absent | no status text at all | **never** hide the row |

Check with a screen reader or the accessibility tree that every non-normal state
carries a spoken label — colour alone is not allowed to be the signal.

`Disabled · N running` deserves its own attention: `disable` only clears a
registry flag, so the sidecar keeps running and paid runs continue. If the row
ever says plain `Disabled` while runs are live, that is the bug this wording
exists to prevent.

### 4.3 Lifecycle controls — new, and the highest-risk surface

On the Optimizers page, `optimizer-plugin-actions` holds buttons matching the
current phase: `plugin-install`, `plugin-enable`, `plugin-start`, `plugin-stop`,
`plugin-update`, `plugin-disable`, `plugin-remove`.

These have **never been clicked**. They call the same native engine agents have
been using, so approval prompts, active-run guards, and receipts are all live.

1. Each action raises its approval prompt. **Reject one** — the UI must show the
   rejection, not report success. Result appears at `plugin-action-receipt`.
2. `Stop` and `Remove` with a live run must be refused natively. Start a run
   first, then try. The refusal must be visible, not silent.
3. `Disable` warns that runs keep going. `Remove` warns what is deleted versus
   retained.
4. After any action, the sidebar row and the page agree — they read one shared
   status now, so disagreement means the refresh path is broken.
5. Recipe-launch buttons are disabled whenever the plugin is not `ready`. This
   is new; confirm it does not block a genuinely ready plugin.

Prefer a scratch data root for the destructive ones.

### 4.4 Traces — inspection and the agent path

1. **Data → Traces**: a compatible row offers `Inspect` and opens
   `trace.rollout_inspector.v1` in the right panel.
2. Reopen the same trace — the **same** visual is reused, no duplicate. Restart
   the app and reopen; still the same one.
3. An unavailable trace shows an honest disabled label — `Quarantined`,
   `Archive incomplete`, or `Unsupported` — and stays visible.
4. **Agent path**, in a Codex session: `trace_manage` with `list`, `get`,
   `open`. `open` must put the inspector in the right panel with no UI driving.
5. `trace_manage` with `query` → returns a snapshot id; `open_query` → opens
   `trace.catalog.v1`. **This template has never been rendered.** Expect to find
   layout problems. Check: the filter is listed as its own clauses, the row count
   and retrieval time are shown, a capped result says so, an empty result states
   the filter rather than going blank, and a missing reward shows `—` not `0`.
6. Ask the agent for SQL, a file path, or a URL through `trace_manage`. It must
   be refused before any request is made.

### 4.5 Regression sweep

Chat, composer, visuals, reports, containers, usage, settings, account menu.
The sidebar restructure and the shared status flow touch the shell, so give the
surrounding surfaces a pass even though they were not the target.

## 5. Known red — do not chase these

1. **Two `test:a11y` failures are deliberate.** `BackendSettings.tsx` has a
   "Synth API key" form — `type="password"` at `:169`, `apiKey` forwarded at
   `:107` — while `:257` still tells the user credentials live only in a native
   env file. Two standing invariants forbid the form and neither was retired, so
   the tests are correctly red. **This is a product decision for Josh, not a
   test fix.** Do not edit the assertions to match the code.
2. **Playwright was already red before this branch**: 31 failures of 188 at
   `4c32e75`, three of them from a suite literally named *"design debt (expected
   fail until fixed)"*.

   On this branch: **34 of 188 under machine load, 33 of 188 on a quiet re-run**
   — so roughly **+2 against the baseline's 31**, and that delta is *not*
   attributed. Both runs were captured with a truncated reporter, so the
   per-test comparison against baseline is unreliable. **Re-run with a full
   reporter on an idle box and diff the failing titles against `4c32e75` before
   concluding anything.** Two findings from triaging what was legible:

   - **One real regression, fixed** (`e2aa167`). The plugin fakes in
     `optimizer-plugin-mcp.spec.ts` answered `status()` but returned `[]` from
     `list()`. The sidebar and the Optimizers page read the listing now, so the
     UI saw no plugin at all. If you write a new plugin fake, it must answer
     `list()`.
   - **Six `mander-lab` failures were load, not breakage.** They pass 6/6 in
     isolation. That spec records video, which is heavy under contention.

   Treat any Playwright failure on a busy machine as suspect until it
   reproduces in isolation — and re-run the suite on an idle box before
   trusting the count either way.
3. **`fixture_install()` still stubs plugin install under `cfg!(test)`**
   (`optimizers/manager.rs:1615`). Lifecycle tests therefore do not exercise a
   real install. Known, deliberately deferred — the opt-in env var is
   process-global and ten tests install, so converting them carelessly trades a
   stub for a flake.

## 6. Behaviour changes worth knowing before you file a bug

- **The 750 ms plugin poll is gone.** Status now arrives on the `optimizer:status`
  event, with a bounded poll only while a phase is transitional. If status feels
  stale, that is the suspect — but note the old poll re-probed the live sidecar
  from every screen and the audit tied it to SIGTERMing paid runs.
- **A disabled plugin now refuses work.** `require_plugin_ready` checks the
  registry flag, not just the sidecar. Previously a disabled plugin with a
  running sidecar would accept a recipe start.
- **The optimizers MCP server now registers even when disabled**, and refuses
  with a typed `plugin_not_ready` instead of vanishing from the tool list.
- **Trace inspector reuse is digest-only.** A re-sealed trace gets a new
  inspector instead of reopening the previous archive under the new name.
