## Release cut

v0.8 ships only when all three P0 journeys are release-qualified:

1. a user can search, inspect, compare, fork, and rerun real experiments through
   a durable lineage/DAG workspace in the Synth frontend;
2. Workshop can run hosted Laguna XS and Laguna S through Shoal with production
   lifecycle, request, accounting, promotion, and rollback receipts; and
3. a user can complete NanoHorizon from `/challenges/nanohorizon`, iterate on
   Modal, and reproduce a selected candidate on Mac MLX, with or without
   Workshop installed.

Experiments and the DAG move into v0.8 P0. NanoHorizon is a top-level frontend
surface beside Evals, not a Workshop feature. Workshop is an optional coding
agent/setup path for NanoHorizon and the desktop client for hosted Laguna.

## Decision register

| ID | Frozen decision |
| --- | --- |
| D01 | `/challenges/nanohorizon` is a top-level frontend destination beside `/evals`; no challenge state or navigation lives in Workshop. |
| D02 | The backend owns the authoritative append-only experiment event log and rebuildable projection. Frontend and Workshop may cache projections for responsiveness/offline viewing but cannot mint authoritative lineage. |
| D03 | `synth.candidate.v1`, `synth.task-contract.v1`, typed edges, immutable receipts, and parity-tested canonical digests are shared contracts across every lane. |
| D04 | NanoHorizon v0.8 freezes one profile: Qwen3.5-0.8B, rank-8 LoRA, the declared four-layer target set, Rust GameBench Craftax gold, and published seeds `91001`-`91010`. |
| D05 | NanoHorizon Modal execution uses a dedicated runner for the current contract. Tito internals may be reused behind it; archived JAX/vLLM challenge code is not a release path. |
| D06 | `synth.adapter.v1` wraps safetensors plus a manifest. Conversion for MLX produces a separate content-addressed artifact with `converted_from` lineage and a nonzero adapter-application probe. |
| D07 | Browser-only, standalone local, and Workshop-assisted onboarding are equal supported paths. The page publishes a signed-manifest-derived, fully visible copyable coding-agent prompt. |
| D08 | The first Modal smoke is hard-capped at ten minutes and USD 1.00; the manifest may lower but not raise those limits. Paid compute and leaderboard publication require separate explicit approvals. |
| D09 | Three compatible control runs are required before the frontend may label NanoHorizon uplift credible. The official score and supporting metrics remain visible independently. |
| D10 | Shoal separates desired service state, observed health, and logical request state. Reconciliation is idempotent; a retry never creates a second logical charge or silently switches serving revision. |
| D11 | User charges are denominated in USD and stored in integer microcents under an immutable tariff version. Admission reserves the declared maximum; settlement charges measured delivered inference and releases the balance. |
| D12 | Synth absorbs cold starts, idle/warm-pool time, canary capacity, provider faults, pre-execution retries, and generated tokens not delivered after infrastructure failure. User-caused cancellation settles only measured delivered usage. Credits and corrections are append-only ledger entries. |
| D13 | XS and S have independent tariff, quota, concurrency, capacity, and SLO records. Production routes stay disabled until every record contains approved non-placeholder values and load evidence. |
| D14 | Code and release workflows never use macOS Keychain credentials. They use only already-authorized project-local `.env` values or Workshop's non-Keychain secrets proxy; secret values never enter experiment data. |

The remaining launch inputs are measured numbers: final XS/S tariff rates,
allowances, concurrency, warm-pool sizes, SLO thresholds, and CUDA/MLX tolerance
bands. Their schemas and gates are fixed here; no implementation should hardcode
guesses.

## Contract spine

The first integration artifact is a small, versioned contract package shared by
all lanes:

- canonical experiment, run, candidate, artifact, evaluation, promotion, and
  trajectory-reference records;
- typed append-only lineage edges;
- service desired/observed transition and request execution receipts;
- reservation, settlement, credit, and reconciliation ledger entries;
- `nanohorizon.submission.v1`, challenge manifest, seed ledger, and evidence
  bundle;
- stable error codes, cursor/event envelopes, and canonicalization fixtures; and
- Python and TypeScript parity tests, with Rust parity where the container/task
  boundary computes a digest.

No product lane may create a competing identity or infer authoritative lineage
from labels, filenames, paths, ports, or timestamps.

## Dependency and delivery order

```text
M0 contracts + launch-config schemas
   ├── E1 backend experiment spine ──> F1 experiment/DAG UI
   ├── C2 task/candidate execution ──> N1 challenge freeze
   │                                   ├── N2 Modal runner ─┐
   │                                   └── N3 Mac MLX ──────┼──> F2 complete challenge journey
   └── S1 Shoal lifecycle ──> S2 economics ──> W1 Workshop + P1 promotion

F1 + F2 + W1 + P1 + retained cross-lane receipts ──> v0.8 release qualification
```

Work starts in this order:

1. land C1 fixtures and approve the launch-config schemas;
2. build E1, C2, and S1 against those fixtures in parallel;
3. publish F1's fixture-backed shell and N1's frozen challenge package;
4. close the real N2 Modal and N3 MLX vertical slice before polishing F2;
5. close S2 before enabling any hosted Laguna production route;
6. integrate W1 and P1, then run product-quality and release gates.

## Milestone gates

### M0 — contracts frozen

- All schemas above have versioned fixtures and parity tests.
- NanoHorizon profile, prompt manifest, budgets, and public seeds are frozen.
- Shoal lifecycle/request/accounting invariants and tariff configuration schema
  are approved.
- No production route or paid challenge path is enabled.

### M1 — experiment spine usable

- Real Eval/GEPA/training/Shoal events rebuild to the same projection.
- Search, node detail, two-node compare, and at least a three-node DAG work on
  migrated and newly emitted data.
- Duplicate/out-of-order events and redacted artifacts are covered.

### M2 — NanoHorizon vertical slice

- Browser fork and credential-free preflight work without Workshop.
- One current-contract Modal smoke trains, saves, reloads, evaluates, and returns
  immutable receipts within the signed cap.
- The exact candidate completes strict Mac MLX verification and renders a
  `reproduced_on` comparison.
- Standalone and copied-prompt setup are reproduced on clean supported Macs.

### M3 — hosted Laguna production candidate

- XS and S pass Responses streaming/tool, retry, cancellation, restart, degraded
  capacity, canary, and rollback tests through Workshop and Shoal.
- Reservation and settlement reconcile with request and infrastructure facts;
  injected races produce no duplicate work or charge.
- Approved tariff/quota/SLO records replace disabled placeholders.

### M4 — product quality

- DAG scale, accessibility, compact-window, deep-link, trace filtering, control
  bands, usage detail, and evidence export pass.
- Security and privacy review confirms redaction and non-Keychain credential
  behavior.

### M5 — release qualification

- Three clean-install journeys retain a signed evidence bundle: experiment/DAG,
  hosted Laguna XS/S, and NanoHorizon Modal-to-MLX.
- Model/service/desktop rollback is rehearsed.
- Release notes, support runbook, SLO dashboards, and go/no-go scorecard are
  complete.

## Integration policy

- Use the `codex/v0.8-*` lane branches above; do not implement in original dirty
  checkouts.
- Rebase or merge the chosen authoritative release head before substantive work
  if its recorded base has advanced; record the resolved base in the PR.
- One PR should close one typed contract or vertical-slice acceptance claim.
- Contract changes land with fixtures and consumer compatibility notes before
  dependent implementations.
- Every external or paid E2E has a credential-free fixture/simulator gate first.
- Live credentials use only already-authorized `.env` or non-Keychain proxy
  mechanisms and are never copied into worktrees, logs, fixtures, or receipts.
- Feature flags default off for paid NanoHorizon runs and hosted Laguna routes.
- Promotion requires immutable candidate, serving, evaluation, economics,
  approval, canary, and rollback receipts.

## First implementation checkpoint

The first checkpoint is deliberately narrow and can be reviewed end to end:

1. C1 publishes canonical TypeScript/Python fixtures for experiment nodes,
   edges, candidates, tasks, and NanoHorizon submission manifests.
2. E1 ingests fixture events and exposes list/get/search/lineage endpoints.
3. F1 renders a fixture-backed experiment list and three-node lineage deep link.
4. N1 validates one starter and one intentionally invalid submission.
5. S1 models XS/S desired/observed transitions and idempotent logical request
   receipts without contacting a GPU.

No paid compute, production route, leaderboard write, or provider credential is
needed to reach this checkpoint.
