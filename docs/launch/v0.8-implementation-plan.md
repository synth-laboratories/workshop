## Release cut

v0.8 ships only when all three P0 journeys are release-qualified:

1. a user can search, inspect, compare, fork, and rerun real experiments through
   a durable local lineage/DAG workspace in open-source Workshop without signing
   in or uploading experiment data;
2. Workshop can run hosted Laguna XS and Laguna S through Shoal with production
   lifecycle, request, accounting, promotion, and rollback receipts; and
3. a user can complete NanoHorizon from `/challenges/nanohorizon`, iterate on
   Modal, and reproduce a selected candidate on Mac MLX, with or without
   Workshop installed.

Experiments and the general DAG move into Workshop v0.8 P0 as a local-first OSS
capability. NanoHorizon remains a top-level hosted frontend surface beside Evals,
not a Workshop feature. Workshop is an optional coding-agent/setup path for
NanoHorizon and the desktop client for hosted Laguna.

| D05 | NanoHorizon Modal execution uses a dedicated runner for the current contract. Tito internals may be reused behind it; archived JAX/vLLM challenge code is not a release path. |
| D06 | `synth.adapter.v1` wraps safetensors plus a manifest. Conversion for MLX produces a separate content-addressed artifact with `converted_from` lineage and a nonzero adapter-application probe. |
| D07 | Browser-only, standalone local, and Workshop-assisted onboarding are equal supported paths. The page publishes a signed-manifest-derived, fully visible copyable coding-agent prompt. |
| D08 | The first Modal smoke is hard-capped at ten minutes and USD 1.00; the manifest may lower but not raise those limits. Paid compute and leaderboard publication require separate explicit approvals. |
| D09 | Three compatible control runs are required before the frontend may label NanoHorizon uplift credible. The official score and supporting metrics remain visible independently. |
| D10 | Shoal separates desired service state, observed health, and logical request state. Reconciliation is idempotent; a retry never creates a second logical charge or silently switches serving revision. |
| D11 | User charges are denominated in USD and stored in integer microcents under an immutable tariff version. Admission reserves the declared maximum; settlement charges measured delivered inference and releases the balance. |
| D12 | Synth absorbs cold starts, idle/warm-pool time, canary capacity, provider faults, pre-execution retries, and generated tokens not delivered after infrastructure failure. User-caused cancellation settles only measured delivered usage. Credits and corrections are append-only ledger entries. |
| D13 | XS and S have independent tariff, quota, concurrency, capacity, and SLO records. Production routes stay disabled until every record contains approved non-placeholder values and load evidence. |
| D14 | Code and release workflows never use macOS Keychain credentials. They use only already-authorized project-local `.env` values or Workshop's non-Keychain secrets proxy; secret values never enter experiment data. |
| D15 | Cloud publication or synchronization is explicit opt-in, disabled by default, and never required for local capture, DAG browsing, comparison, rerun, or export. Workshop previews the exact records/artifacts leaving the machine and retains a publication receipt. |
| D16 | Experiments are the first domain on the reusable local journal/projection/CAS/export foundation. Later local-first abstractions may reuse that infrastructure through their own versioned types and migrations; they are not forced into experiment nodes and are not part of the v0.8 cut. |

The remaining launch inputs are measured numbers: final XS/S tariff rates,
allowances, concurrency, warm-pool sizes, SLO thresholds, and CUDA/MLX tolerance
bands. Their schemas and gates are fixed here; no implementation should hardcode
guesses.

## Local experiment storage architecture

The experiment system is an evolution of Workshop's existing Rust CoreRuntime,
not a new backend service:

| Concern | Local owner |
| --- | --- |
| Domain implementation | `apps/synth_desktop/src-tauri/src/experiments.rs`, expanded beyond its current bounded session grouping |
| Durable metadata and indexes | Workshop's existing `synth.sqlite3` through forward-only Rust migrations and WAL |
| Append-only facts and subscriptions | Existing CoreRuntime event journal, with experiment event kinds and idempotency keys |
| Large artifacts, traces, checkpoints, and exports | Existing Workshop content-addressed `store/` roots; SQLite stores digests and relationships rather than large bodies |
| Local query/mutation boundary | Typed CoreRuntime/Tauri commands and generated renderer protocol; never renderer `localStorage` |
| DAG presentation | Workshop renderer components and local layout/view state |
| Portable interchange | Content-addressed experiment/evidence bundle with schema and digest manifest |
| Cloud interoperability | Optional publisher/importer adapter with origin mapping, redaction preview, explicit approval, and receipts |

CoreRuntime remains the single SQLite writer. Optimizers, Containers, local MLX,
and hosted clients submit typed facts through Workshop-owned commands rather than
opening the database or writing graph tables directly. The projection and search
indexes are disposable and rebuildable; the journal, immutable manifests, and
content-addressed evidence are the recovery inputs.

Local and cloud identity are related without conflating authority. A local
experiment can be exported without publication. If a user explicitly publishes
it, Workshop records the local ID, remote ID, selected digests, redaction policy,
and publication receipt. Importing a cloud run records its remote origin and a
local immutable snapshot; it does not make future background synchronization
implicit.

The storage foundation is intentionally reusable, but the domain layer is not a
generic property graph. Future abstractions should share database ownership,
event envelopes, content addressing, export/import, and explicit publication
mechanics while defining their own schemas, invariants, projections, and UI.
That keeps v0.8 implementable and avoids baking unknown future products into the
experiment contract.

## Contract spine

The first integration artifact is a small, versioned local experiment contract
owned by Workshop CoreRuntime and mirrored through generated consumer types:

- canonical experiment, run, candidate, artifact, evaluation, promotion, and
  trajectory-reference records;
- typed append-only lineage edges;
- service desired/observed transition and request execution receipts;
- reservation, settlement, credit, and reconciliation ledger entries;
- `nanohorizon.submission.v1`, challenge manifest, seed ledger, and evidence
  bundle;
- stable error codes, cursor/event envelopes, and canonicalization fixtures; and
- Rust/TypeScript/Python parity tests, with Rust as the canonical local storage
  implementation and additional parity where the container/task boundary
  computes a digest.

No product lane may create a competing identity or infer authoritative lineage
from labels, filenames, paths, ports, or timestamps.

## Dependency and delivery order

```text
M0 local contracts + launch-config schemas
   ├── W0 Workshop local store ──> W1 local experiment/DAG UI
   │                          └──> E1 optional cloud publication
   ├── C2 task/candidate execution ──> N1 challenge freeze
   │                                   ├── N2 Modal runner ─┐
   │                                   └── N3 Mac MLX ──────┼──> F2 complete challenge journey
   └── S1 Shoal lifecycle ──> S2 economics ──> W2 Workshop + P1 promotion

W1 + F2 + W2 + P1 + retained cross-lane receipts ──> v0.8 release qualification
```

Work starts in this order:

1. land W0 local schemas, SQLite migrations, journal/projection fixtures, and
   launch-config schemas;
2. build W1, C1, and S1 against those fixtures;
3. build C2, the optional E1 publisher, and N1's frozen challenge package;
4. close the real N2 Modal and N3 MLX vertical slice before polishing F2;
5. close S2 before enabling any hosted Laguna production route;
6. integrate W2 and P1, then run product-quality and release gates.

## Milestone gates

### M0 — contracts frozen

- All schemas above have versioned fixtures and parity tests.
- NanoHorizon profile, prompt manifest, budgets, and public seeds are frozen.
- Shoal lifecycle/request/accounting invariants and tariff configuration schema
  are approved.
- No production route or paid challenge path is enabled.

### M1 — local experiment spine usable

- A clean offline Workshop install captures real Eval/GEPA/training/Shoal events
  into local SQLite/CAS and rebuilds the same projection without an account.
- Search, node detail, two-node compare, and at least a three-node DAG work on
  migrated and newly emitted data.
- Duplicate/out-of-order events and redacted artifacts are covered.
- Network denial tests prove that capture, browsing, comparison, rerun, and
  export do not attempt cloud upload.
- Optional publication shows a redaction preview and produces matching local and
  remote receipts only after explicit approval.

### M2 — NanoHorizon vertical slice

- Browser fork and credential-free preflight work without Workshop.
- One current-contract Modal smoke trains, saves, reloads, evaluates, and returns
  immutable receipts within the signed cap.
- The exact candidate completes strict Mac MLX verification and renders a
  `reproduced_on` comparison.
- Standalone and copied-prompt setup are reproduced on clean supported Macs.

### M3 — hosted Laguna production candidate

- XS and S pass Responses streaming/tool, retry, cancellation, restart, degraded
  capacity, canary, and rollback tests through Workshop and Shoal.
- Reservation and settlement reconcile with request and infrastructure facts;
  injected races produce no duplicate work or charge.
- Approved tariff/quota/SLO records replace disabled placeholders.

### M4 — product quality

- DAG scale, accessibility, compact-window, deep-link, trace filtering, control
  bands, usage detail, and evidence export pass.
- Security and privacy review confirms redaction and non-Keychain credential
  behavior.

### M5 — release qualification

- Three clean-install journeys retain a signed evidence bundle: experiment/DAG,
  hosted Laguna XS/S, and NanoHorizon Modal-to-MLX.
- `V08-CUA-NH-001` completes the fixed idea-to-draft-PR NanoHorizon capstone
  within its cold-start time budget.
- Model/service/desktop rollback is rehearsed.
- Release notes, support runbook, SLO dashboards, and go/no-go scorecard are
  complete.

## CUA capstone: idea to NanoHorizon draft PR

Acceptance ID: `V08-CUA-NH-001`

This is the release-level proof that Workshop and NanoHorizon compose into one
usable workflow. Component tests, a scripted runner invoked outside Workshop,
or a PR made manually after the run do not satisfy it.

### Fixed test intent

Give the coding agent this user-level idea, without implementation instructions:

> Make one small, challenge-legal change intended to reduce NanoHorizon policy
> calls that finish without the required Craftax tool call. Add a focused
> regression test, run the smallest useful experiment first, and prepare a
> reviewable submission PR with the evidence.

The test measures workflow correctness and time, not whether this one hypothesis
beats the baseline. A valid non-improving result may pass; hidden evaluator edits,
an invalid adapter, missing evidence, or an unreported failed experiment may not.

### Preconditions

- Use a signed v0.8 candidate in a fresh named CUA instance and a fresh Workshop
  data root, with no NanoHorizon project already registered.
- Use a dedicated acceptance fork and base commit from the signed challenge
  manifest. The target is a draft PR; the test never merges or publishes a
  leaderboard submission.
- The Mac satisfies the declared Apple Silicon/MLX requirements.
- Git push and draft-PR credentials are already authorized through an SSH file,
  project-local `.env`, or Workshop's non-Keychain secrets proxy. No macOS
  Keychain access or interactive credential repair is permitted.
- Modal credentials, budget, and a full-run maximum spend are present through
  the same allowed mechanisms. The test records spend but never exposes secret
  values.
- The CUA recorder captures monotonic timestamps, screenshots/video, Workshop
  diagnostics, local experiment IDs, process ownership, Git commit, PR URL, and
  the final receipt manifest.

### User journey

1. Start the stopwatch when the tester opens `/challenges/nanohorizon` with no
   local project prepared.
2. Copy the signed-manifest-generated Workshop setup prompt, open a new Workshop
   coding task, select an empty project directory, and paste the prompt.
3. Let the coding agent inspect prerequisites, clone the pinned refs, create a
   `codex/cua-nanohorizon-*` branch, materialize the starter, and run the
   credential-free preflight. The tester issues no terminal commands.
4. Give the fixed test intent. The agent explains its hypothesis, edits only the
   admitted submission surface, adds a focused test, and shows the source diff.
5. Run the local tests and no-cost mechanism smoke. A failure must appear as a
   durable local experiment node with an actionable diagnostic.
6. From Workshop, request the bounded Modal smoke. Verify the approval sheet
   shows source/task/config digests, backend, clock cap, USD 1.00 maximum, and
   cancellation behavior. Pause the stopwatch only while waiting for the human
   approval; do not exclude provisioning or compute time.
7. Inspect the completed smoke through Workshop's local experiment list and DAG.
   It must show starter → fork → preflight → smoke lineage, trace/tool-validity
   evidence, artifact identity, cost, and terminal state without cloud upload of
   the local Workshop graph.
8. If the smoke passes, request the official-shaped bounded run. Show its exact
   maximum time and manifest-defined maximum spend and obtain a second explicit
   approval. Train, evaluate with challenge-owned code, seal the result, and
   retain failed attempts as nodes.
9. Run the selected candidate through the bounded local MLX compatibility smoke
   and paired verification. Record conversion lineage and the cross-backend
   verdict without claiming bit equivalence.
10. Ask the agent to prepare the submission. It validates portability and
    challenge rules, excludes secrets/caches/weights and host-absolute paths,
    writes the evidence manifest, and presents `git status`, the diff summary,
    tests, score/limitations, spend, and proposed PR title/body.
11. After explicit approval, the agent commits, pushes through the preauthorized
    non-Keychain Git mechanism, and creates a draft PR against the acceptance
    target. CUA opens the returned PR URL and verifies its base/head commits,
    changed files, evidence references, and initial CI state.
12. Quit and relaunch Workshop with networking denied. The local experiment DAG,
    traces, receipts, Git/PR reference, and terminal states must still reopen.

### Time budget

| Checkpoint | Cold-start ceiling |
| --- | ---: |
| Challenge page to passing credential-free preflight | 15 minutes |
| Idea to tested diff and no-cost mechanism smoke | 15 additional minutes |
| Bounded Modal smoke visible in the local DAG | 15 additional minutes |
| Official-shaped run, MLX verification, evidence bundle, and draft PR | 45 additional minutes |
| Total, excluding only recorded human approval latency | 90 minutes |

The receipt reports both full wall time and approval-excluded active-system time.
No stage may hide setup, queueing, retries, or manual remediation by resetting its
clock. A run over 90 minutes fails the release gate even if it eventually works.

### Pass criteria

- The tester uses CUA and Workshop UI only: no manual shell choreography, port
  repair, file editing, Git command, or browser/API workaround.
- The coding agent reaches the correct pinned project from the page's copied
  prompt and never modifies challenge-owned evaluator or held-out data.
- Preflight, tests, Modal smoke, official-shaped evaluation, MLX verification,
  evidence export, commit, push, and draft PR all have retained terminal
  receipts. Quality uplift is not required; validity is.
- The local experiment graph is authoritative and survives relaunch offline.
  Nothing leaves the machine before the corresponding explicit run, receipt
  publication, Git push, or draft-PR approval.
- Every graph edge is backed by a typed fact; failed/retried attempts remain
  visible; no artifact, score, request, or charge is duplicated.
- The draft PR contains only the admitted source/config/tests and portable
  evidence references, with exact base/head commits and no secret, weight,
  cache, absolute path, generated local database, or unrelated dirty change.
- All child processes are owned and terminal at the end. No stale container,
  sampler, trainer, daemon, lease, or occupied acceptance port remains.
- Any crash, Keychain prompt/access, hidden credential request, manual recovery,
  silent upload, missing receipt, invalid official result, or non-draft external
  publication is an immediate failure.

## Integration policy

- Use the `codex/v0.8-*` lane branches above; do not implement in original dirty
  checkouts.
- Rebase or merge the chosen authoritative release head before substantive work
  if its recorded base has advanced; record the resolved base in the PR.
- One PR should close one typed contract or vertical-slice acceptance claim.
- Contract changes land with fixtures and consumer compatibility notes before
  dependent implementations.
- Every external or paid E2E has a credential-free fixture/simulator gate first.
- Live credentials use only already-authorized `.env` or non-Keychain proxy
  mechanisms and are never copied into worktrees, logs, fixtures, or receipts.
- Feature flags default off for paid NanoHorizon runs and hosted Laguna routes.
- Promotion requires immutable candidate, serving, evaluation, economics,
  approval, canary, and rollback receipts.

## First implementation checkpoint

The first checkpoint is deliberately narrow and can be reviewed end to end:

1. W0 evolves the existing `experiments.rs` grouping model into canonical local
   nodes/edges, adds forward-only SQLite migrations, journals idempotent events,
   and rebuilds its projection from fixtures.
2. W1 renders a local fixture-backed experiment list and three-node lineage deep
   link entirely through CoreRuntime/Tauri commands.
3. C1 publishes matching Python fixtures for candidates, tasks, event envelopes,
   and NanoHorizon submission manifests.
4. N1 validates one starter and one intentionally invalid submission.
5. S1 models XS/S desired/observed transitions and idempotent logical request
   receipts without contacting a GPU.

No network, Synth account, cloud upload, paid compute, production route,
leaderboard write, or provider credential is needed to reach this checkpoint.
