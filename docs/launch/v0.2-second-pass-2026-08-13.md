## Verbatim — second deep pass (2026-08-13)

Deep pass complete — five more reviewers over the unpushed commit stack, the Containers tip, the renderer, the modern-stack delta, and G4 release engineering. Full consolidated report (both sweeps): ⧉
https://claude.ai/code/artifact/9d4b23ef-404a-4fc2-b9c2-62c0d1e50e2c

What this pass found that the first one didn't

Three release blockers, two of them empirically reproduced in Containers — the repo the plan calls "clean at 44443b4":

1. Concurrent identical start_rollout calls corrupt the journal permanently. CompatPlatform has no lock while app.py deliberately dispatches via asyncio.to_thread. Reproduced: both calls execute (the receipted
idempotency rule breaks), they collide on one shared seal .tmp path, the crash path leaks a lease, and duplicate sequences persist — after which recover() fails event_log_sequence_gap forever. http_adapter has
its own check-before-await version of the race. Fixes are small (RLock, try/finally, unique temp name), but the suite has zero concurrency tests, which is exactly where this lived.
2. Façade restart + re-prepare bricks the journal. RolloutEventLog.recover is only ever called by tests — prepare() lays a fresh log over an existing journal and appends sequence: 1 after the old tail, making it
unrecoverable. Spool reopen is receipted; the journal equivalent is broken. Containers needs a fix commit before it becomes the release pin.
3. The Desktop stop-fence swallows user messages. The new stop-during-handshake check (useAppController.ts:986) reads a fence that failTurnStart and cancel also set but only sendTurn clears — after any failed
turn start, the user's next message is silently auto-interrupted while its optimistic bubble stays in the transcript.

The reconciliation is bigger than "reconcile intentionally": all 7 modern-stack commits must cherry-pick into the tip — the Harbor A2, V5/V6, and O-gate receipts depend on code that exists only on that branch,
with zero subject overlap with the main line. projectEvents.ts is a three-way conflict (main + modern + a second live agent's uncommitted +269-line SFT lane in the modern worktree), and the modern worktree's
w1-w3-cua.json differs in content from the committed one — rename, never overwrite.

G4's recording half doesn't exist: the dirty-tree gate is real and secrets sweeps are clean (three independent passes, zero hits), but there's no provenance generator, no CDHash/SHA capture, no friends-ZIP
producer (install deletes the .app after staging), synth-trace isn't bundled — so a friends install fails closed on trace ingest with a dev-only remedy message — and the containers pin is a directory label that
nothing --version-verifies.

Smaller but shippable-quality items: a three-way RendererKind spelling drift (systemsDynamic vs systems-dynamic across serde, generated protocol, and runtime-protocol — masked only by a templateId fallback); two
genuine missing≠0 violations in shipped visuals (dig.bench "Malformed" fabricates 0, GEPA evidence-integrity shows "complete" from number-free events); the Bombadil stubs predate the OAuth/permissions contract so
the receipted approval specs exercise the disconnected branch; an unresolved approval card is invisible on restored sessions; and a "no UI commentary" rule violation plus a pane literally labeled "Benjamin
Dicken Style" in VisualHost.tsx:415.

On the positive side, the deep pass confirmed the core honesty machinery: persist-before-publish ordering, cursor/backfill exactness, no-guessed-URLs, reward-null propagation, PNG path-traversal safety,
backpressure without bypass, OAuth file hygiene, and SVG injection defenses are all verified clean.

Suggested order (detail in the artifact): Containers fixes + tests first (the pin depends on it), then stop-fence/approval/Bombadil (they gate the G3 live checks), then the four G1 code items + receipt, then the
G2 split with the 7 cherry-picks, then G4 tooling. Memory is updated so follow-up sessions inherit all of this.
