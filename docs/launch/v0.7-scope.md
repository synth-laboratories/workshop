## Optimizers runtime (locked 2026-08-19)

One Workshop noun, one local runtime, then search vs training:

```text
Workshop OptimizerService
  durable runs, events, visuals, approval, MCP recipes
        |
        v
Optimizers sidecar          ← one local runtime (the plugin)
  admission, capabilities, cancel, event producer
        |
        +-- Search (optimizers)
        |     local  GEPA  → sidecar worker
        |     hosted GELO  → Synth Cloud (admit + reconcile; not a v0.7 GELO ship)
        |
        +-- Training
              local  SFT / CISPO → synth-mlx-rl
              hosted SFT / CISPO → public API / Optimizers Beta / Tinker
```

`OptimizerService` does not dial MLX, Tinker, or a task container. The
sidecar admits the recipe and dispatches. Placement is the recipe id
(`sft.qwen35-0.8b.mlx.v1` vs hosted SFT; local CISPO vs `cispo.slime.v1`),
not a second product surface. Local eval recipes remain host-owned and
do not install the plugin.

Today GEPA uses this shape; SFT/CISPO bypass the sidecar (`mlx_sft.rs`,
`sft_client.rs`, hosted-CISPO agent/SDK). Closing that gap is the
training implementation.
