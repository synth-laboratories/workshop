### Optimizer sidecar as first-class compute (Laguna analog; not A1–A8; do not mix into SYN-3202)

Treat local optimizer compute the way Laguna treats on-device models: **shown, downloadable, start/stoppable**, including Compose as a packaging option. **Optimizers page owns download/lifecycle.** **Agents get MCP for the same status and lifecycle.** Runs stay a second layer. Sidecar install is not a recipe. Hosted GELO/SFT stay “available via Synth / optimizers-beta” and do **not** require a local sidecar.

Today Tauri already has `optimizer_sidecar_{status,install,start,stop,version,uninstall}`. The Optimizers page is run-centric (recipe start + run list). MCP `optimizer_manage` is run-centric (`list_algorithms` / `list_recipes` / `start_recipe` / watch). Agents cannot see “GEPA local is not installed.” Compose discover is design-only in [`live_optimizers_gepa.md`](../live_optimizers_gepa.md); current `docker-compose.yml` has no optimizer service. `OptimizerManager` (Laguna analog) owns process lifecycle; `OptimizerService` owns the durable mirror. Stopping the sidecar must not delete runs/visuals.

**Split**

| Surface | Owns | Does not own |
| --- | --- | --- |
| **Optimizers page** | Catalog card, download progress, install/start/stop/uninstall, packaging (Desktop process vs Compose `optimizer-gepa`), health, digest/version | Recipe hyperparameters, `/events` URLs, hosted GELO/SFT compute |
| **MCP `optimizer_manage`** | Same sidecar truth agents can poll; mutate only with explicit user approval | Shell `uv` / `docker compose`, compose YAML, images, ports, credentials |
| **Run layer** (already there) | `list_recipes` / `start_recipe` / watch / visual | Auto-downloading a sidecar in the background |

```text
Optimizers page / MCP
        ↓
OptimizerManager.install(version, packaging)
        ├─ desktop  → uv/synth-optimizers child on loopback
        └─ compose  → opt-in profile, same /health + event pages
        ↓
auth proxy (Workshop token)
        ↓
OptimizerService mirror + visual
```

Same HTTP contract either packaging. Workshop still owns pin/health/auth proxy/mirror. Default Workshop Compose stack must **not** depend on `optimizer-gepa`. Pin is `sidecar_version × algorithm_version × recipe_version`. Uninstall ≠ delete runs/visuals. Active run blocks uninstall of **that** version.

**Page (Laguna analog)** — a **Local compute** strip above the run list, not buried in Settings:

| Card | State | Actions |
| --- | --- | --- |
| **GEPA sidecar** | not installed / downloading / installed·stopped / ready · digest · version | Download, Start, Stop, Uninstall |
| **Packaging** | Desktop process (default) **or** Compose `optimizer-gepa` | same contract either way |
| **Hosted GELO / SFT** | available via Synth / optimizers-beta | no local download |

Download is a signed catalog hit (version + digest + algorithms + template ids), progress on the card, then Start. History and visuals remain when the sidecar is stopped. `list_recipes` marks local GEPA `unavailable` until ready, with a precise blocker (`sidecar_not_installed` / `sidecar_stopped`), not a guessed `uv` command.

**MCP** — keep one compact tool. Add sidecar ops next to run ops. Do not let chat supply compose files, images, or ports.

```text
optimizer_manage
  # sidecar (new)
  sidecar_status
  sidecar_list_versions          # catalog: digest, algorithms, size, packaging
  sidecar_install                # version? packaging: desktop | compose
  sidecar_start | sidecar_stop
  sidecar_uninstall              # blocked if an active run is pinned to that version

  # runs (already there)
  list_algorithms | list_recipes
  start_recipe                   # fails closed if local GEPA and sidecar not ready
  list_runs | get_run | watch_run | get_state
  cancel_run | open_visual
```

`sidecar_status` returns what the page shows: `phase`, `version`, `digest`, `packaging`, `baseUrl` (loopback only), `algorithms`, `activeRunIds`. No API keys, no compose YAML. Install/start/stop/uninstall need the same bar as `start_recipe`: **explicit user approval**. Status/list/versions do not.

## What the product now is

```text
Workshop visual-first control
        ↓
Optimizer / Containers lifecycle
        ↓
Canonical streamed events
        ↓
Inspectable live projection
        ↓
Durable journal + reward + Trace V5
        ↓
Reopen after service/container death
```

Containers owns rollout execution, pins, durable trace logs, rewards, leases, and replay.
Optimizers owns GEPA/SFT campaigns and typed links to child rollouts.
Workshop binds declared streams before mutation, persists events, renders live evidence, multiplexes concurrent runs, and reopens durable state.

Invariants that now have live evidence:

- Visual readiness precedes mutation.
- Missing values remain missing, not zero.
- Promotion is distinct from checkpoint readiness.
- Child resources and candidates are inspectable.
- Proposer output streams incrementally.
- Retries do not duplicate execution.
- Durable evidence is authoritative over the browser.
- Authentication changes do not change run or stream identity.
- Tokens do not enter receipts or traces.
