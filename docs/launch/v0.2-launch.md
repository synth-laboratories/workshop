## Capture truth — `capture_review` is not a responsive capture (merge blocker)

**Do not merge the dirty tree wholesale.** `7abed18` is a reasonable visual checkpoint, but the "compact viewport" half of universal QA does not do what the Ships row claimed.

`capture_desktop_review` ([`synth_visuals_mcp.rs:579-645`](../../apps/synth_desktop/src-tauri/src/bin/synth_visuals_mcp.rs)) shows the visual, resolves the **existing** on-screen window via `CGWindowListCopyWindowInfo`, captures it with `screencapture -x -l <window_id>`, then resamples that bitmap with `sips -z <height> <width>`. The requested viewport never reaches the renderer. A "768×1024 compact review" is the desktop-sized layout **resampled**, not a visual that reflowed at 768 px.

Two aggravating details:

- `sips -z` forces exact dimensions and does **not** preserve aspect ratio, so the review image is also geometrically distorted — a squashed picture of the wide layout, which misinforms the reviewing agent about spacing and density.
- The window resolver filters `width >= 640, height >= 400`, so a genuinely narrow window could not be selected even if one existed.

The SVG path (`mermaid` / `systems` / `systemsDynamic`) is a real render at the requested size and is not affected by this. The claim to fix is the React/template path.

**Work**

1. Render or resize the actual visual surface to the requested viewport before capture, then restore prior state. Different viewports must produce different **layout geometry**, not different PNG dimensions.
2. Detect macOS TCC denial and reject black/blank captures with decoded pixel checks — `screencapture` can exit 0 having written an empty image, which passes today's `success() && is_file()` guard.
3. Add an explicit platform enum. Unsupported platforms return an actionable `UnsupportedCapturePlatform`, not `launch sips: No such file or directory`. There is no `#[cfg(target_os = "macos")]` anywhere in the file today, so off-macOS the authoring gate is unsatisfiable with a confusing error.
4. Replace the `sips` SVG rasterizer with one canonical renderer that supports the SVG features we allow. Measured: `sips` exits 0 and silently drops `<foreignObject>` content entirely.
5. Test that wide and compact captures differ in layout geometry, not merely in PNG dimensions. That assertion is what makes the claim honest.

Until 1 and 5 land, do not advertise responsive/compact QA for React/template visuals. Readiness gating and attached images are real and can stay.

## Optimizer supervisor safety (isolated P0 commit)

The dirty `manager.rs` diff fixes the leak it targeted but **introduced two regressions**. `HashSet::insert` was an atomic check-and-insert; splitting it into `HashMap` check (`:524-527`) + insert-after-spawn (`:542-545`) created a TOCTOU where the second insert overwrites the first pid, leaving the first process group permanently untracked and surviving the drain. And `abort_runtime` (`:791-796`) now **hangs app quit on non-unix**: the group terminate is a no-op there, `child.id()` returns `Some` so the kill branch is skipped, and `child.wait()` blocks forever. Pre-diff this was an unconditional `child.kill()` and worked.

Model the worker explicitly rather than adding another flag:

```text
Vacant → Starting → Running(pid) → Stopping → Vacant
```

Reserve `Starting` atomically with the map entry API under one lock, spawn with the lock released, then promote to `Running(pid)`. **Promotion must fail closed:** if shutdown drained the map during the spawn, the reservation is gone — terminate the just-spawned process group and return an error rather than re-inserting a pid the drain has already read past.

Holding the lock across the spawn is **not** an acceptable alternative: `ensure_memory_spool` awaits a *different* mutex between check and spawn (lock-order hazard), and the method's own doc comment states the map exists so two runs can be live at once. Holding it would serialize exactly what the design forbids.

Also in this commit:

- Restore non-unix child termination — one helper that group-terminates, then unconditionally `child.kill()`, then `wait()`.
- Terminate process groups on **release** and **cancellation**. `recipes.rs:221` only removes the map entry, and `recipes.rs:436` kills `uv` alone — now that `process_group(0)` is set, that orphans the Python child under a dead leader. These are the paths that actually leak in practice, and the current diff does not touch them.
- Stop normal app shutdown from relabeling active paid runs as generic failures: `stop()` has no active-run guard, so a clean quit surfaces live runs as `bail!("… exited with …")`. Distinguish shutdown from failure in the terminal event.
- Name the SIGTERM→SIGKILL grace in `limits.rs` beside `LAGUNA_STOP_TIMEOUT`. 150 ms will not cover a uv/Python spool flush; use a bounded poll to a 500 ms deadline rather than a flat sleep, so a fast exit does not tax every quit.
