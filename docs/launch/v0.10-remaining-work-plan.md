# v0.10.x remaining work plan

Prepared 2026-09-09. Planning baseline: Workshop `86f6ac78` on `codex/v010-complete`.

## Distribution amendment — user decision, 2026-09-09

Ship v0.10 as an explicitly **ad-hoc signed, non-notarized** macOS app, with
first-class build-from-source scripts in the public Workshop repository.
Apple Developer enrollment, Developer-ID signing, notarization and stapling
are **not gates for this release**; their requirements below are superseded.
No Gatekeeper/Developer-ID approval may be claimed. Preserve archive integrity,
provenance, checksums, public download/install acceptance and clear macOS
first-launch instructions. Verify the source build from a clean checkout using
only public pinned inputs, without sibling repositories, credentials or TBLite.
This amendment changes distribution policy, not the remaining product, CI,
migration, staging, production, or public-install gates.

This is the implementation order for finishing the release. The [execution record](v0.10-release-execution-2026-09-09.md) records observations; the [publication checklist](v0.10-publication-and-production-checklist.md) supplies the detailed operator checks. This plan takes precedence over older handoff claims that TBLite must publish before production or that the original candidate can be merged unchanged. This planning pass changes documentation only.

## Scope and defaults

- Release Workshop, its required backend/frontend changes, and the standalone Containers/Optimizers package cuts. Deploy changed Railway services and the frontend through their existing mechanisms.
- **TBLite is eval/testing-only.** It must not appear in production dependency metadata, production installation, or release GO criteria. No TBLite publication is required.
- Keep Workshop's certified embedded Optimizers source `137fe713…` / version `0.2.21`; keep the other embedded runtime pins unless reconciliation demonstrates a necessary change. Publish standalone Containers `0.4.2` then Optimizers `0.2.22` independently. Workshop embeds its runtime, so these PyPI publications do not by themselves gate desktop installation.
- Target Workshop `0.10.0` if it remains unused at execution time. Never replace public bytes or reuse a published tag; use the next patch version if needed.
- Keep Reports in its documented read-only unhosted mode. Defer Reports hosting, Containers artifact linkage, migration-72/symlink consolidation, and the standalone Optimizers repin.
- Plan to exclude Jesterky from this cut and retain its empty catalog. Its signed macOS distribution is separate follow-up work unless explicitly brought into scope.
- Preserve the existing release authorization. Credential availability and product-enforced approvals are separate from that authorization. No macOS Keychain use without authorization for the specific operation; no paid experiment is implied by this plan.
