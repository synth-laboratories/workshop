# Handoff: configurable OpenRouter models in Workshop v0.8

Status: implementation-ready design
Date: 2026-08-25
Concrete acceptance model: `stealth/ox-alpha`

## Outcome

A user can add or remove an OpenRouter model by editing Workshop's local
`config.toml`, relaunch Workshop, and see the model in the launch and composer
pickers without rebuilding the application. A configured model uses the existing
OpenRouter credential lease, Codex app-server adapter, usage ledger, experiment
facts, and recovery path. Configuration never contains a secret or a guessed
price.

This is a general catalog feature. Do not add an `OPENROUTER_OX_ALPHA_MODEL`
constant or another `openrouter-ox-alpha` switch branch.

## Why this is needed

The execution substrate is already generic: Rust persists a
`RuntimeTarget::RemoteRuntime { model, adapter }`, Codex home generation accepts
an OpenRouter model string, and usage records key by provider and model. The UI
catalog is not generic. Adding Gemini required model-specific code in all of:

- `apps/synth_desktop/src/renderer/src/types/landing.ts`
- `apps/synth_desktop/src/renderer/src/runtime/modelCapabilities.ts`
- `apps/synth_desktop/src/renderer/src/runtime/sessionView.ts`
- `apps/synth_desktop/src/renderer/src/runtime/modelPerformanceLabels.ts`
- `apps/synth_desktop/src/renderer/src/components/SettingsPage.tsx`
- `apps/synth_desktop/src-tauri/src/tariffs.rs`

Unknown remote models are currently projected back to Laguna S in
`executionTargetToUiId`. That is an identity bug for configurable models and
must be removed before this feature ships.

## OpenRouter facts checked on 2026-08-25

OpenRouter's public Models API currently returns:

| Field | Value |
| --- | --- |
| Exact model ID | `stealth/ox-alpha` |
| Display name | `Ox Alpha` |
| Context | `1_048_576` tokens |
| Inputs | text, image, video |
| Output | text |
| Tools | supported |
| Reasoning controls | `reasoning`, `reasoning_effort`, `include_reasoning` |
| Maximum completion | `131_072` tokens |
| Current published prompt/completion price | `0` / `0` |
| Published expiration | `2098-12-31` |

The model ID is `stealth/ox-alpha`, not `openrouter/ox-alpha`. Treat all other
metadata as observed provider metadata, not source-owned truth. OpenRouter's
`GET /api/v1/models` exposes context, modalities, pricing,
`supported_parameters`, default parameters, and expiration. OpenRouter may
route among provider endpoints; the response's model/router metadata and usage
remain the execution truth.

- https://openrouter.ai/docs/api/api-reference/models/get-models
- https://openrouter.ai/docs/guides/routing/provider-selection

## User configuration

Extend the existing instance-local Workshop `config.toml` with an array of
tables. The minimal entry is intentionally small:

```toml
[[models.openrouter]]
id = "ox-alpha"
model = "stealth/ox-alpha"
enabled = true
```

Optional presentation and policy fields:

```toml
[[models.openrouter]]
id = "ox-alpha"
model = "stealth/ox-alpha"
display_name = "Ox Alpha"
enabled = true

[models.openrouter.routing]
allow_fallbacks = false
require_parameters = true
data_collection = "deny"

[models.openrouter.ui]
reasoning_control = "effort" # none | binary | effort
default_reasoning = "high"
```

Rules:

- `id` is a stable local identity: lowercase ASCII letters, digits, `_`, and
  `-`; it must be unique. The UI target key is `openrouter:<id>`.
- `model` is the exact OpenRouter slug or `@preset/...`; it is never rewritten
  to a built-in model and never used as a fallback list implicitly.
- This v0.8 cut supports provider `openrouter` only. Do not add arbitrary base
  URLs, headers, commands, or credential-variable names to this table.
- Unknown keys and duplicate IDs fail config validation with a line-addressable
  diagnostic. One bad custom entry must not erase built-in targets.
- `enabled = false` hides the target from new sessions but retained sessions
  continue to reopen with their pinned provider/model identity.
- No price fields. No raw API key. No system prompt. Generation parameters
  beyond the admitted UI controls remain out of this first cut.
- Routing is explicit. In particular, do not silently change models mid-turn.
  If provider endpoint fallback is admitted, preserve OpenRouter router metadata
  so the requested and actually served routes are distinguishable.

## Native catalog contract

Make Rust the catalog authority. Add a typed projection returned through Tauri,
rather than letting the renderer parse TOML:

```text
ModelCatalogEntry {
  target_id,
  provider,
  model_id,
  display_name,
  source: builtin | user_config,
  enabled,
  availability: ready | credential_required | unverified | unavailable | expired,
  capabilities,
  metadata_observed_at,
  metadata_source,
  diagnostic,
}
```

Suggested implementation home:

- parsing/validation: `src-tauri/src/synth_config.rs`
- catalog projection and OpenRouter metadata cache: new
  `src-tauri/src/model_catalog.rs`
- generated renderer type/command: `model_catalog()` plus
  `model_catalog_refresh()`

The resolved catalog is the union of source-owned built-ins and validated user
entries. Preserve target identity directly in sessions; never recover it by
comparing model names after the fact.

### Metadata and offline behavior

1. Parse the TOML without network access.
2. Load the last provider-metadata snapshot from the instance data root.
3. Return the catalog immediately so application startup is never blocked on
   OpenRouter.
4. If network is available, refresh OpenRouter metadata asynchronously with a
   short timeout, conditional request/cache timestamp, and bounded response.
5. Store only public model metadata and its digest/observation time. Never store
   the API key or request it for the public model list.
6. A never-verified model is visible as **Unverified**. It may not advertise
   images, tools, reasoning, context size, or pricing merely from its name.
7. A previously verified model can remain selectable offline with a visible
   “metadata checked …” label. The request itself naturally fails offline; do
   not substitute another target.
8. If OpenRouter removes or expires the slug, show **Unavailable/expired** and
   disable new turns while preserving historical sessions and receipts.

For the first implementation, capability overrides in TOML should only narrow
provider-discovered capabilities. They must not assert that an unsupported
parameter exists. The `ui` block above chooses how to expose a discovered
reasoning capability; it does not create that capability.

## Renderer migration

Replace the static OpenRouter portion of `EXECUTION_TARGETS` with catalog data.
Built-in local, ChatGPT subscription, Synth Cloud, and Intern targets may remain
source-owned, but all OpenRouter targets should use the same projection path so
custom and curated models cannot drift.

Required changes:

1. `useAppController` loads `model_catalog()` before selecting/restoring the
   active target and subscribes to config/catalog changes.
2. `LandingPage`, `Composer`, and Settings render catalog entries rather than
   reconstructing model rows independently.
3. `targetIdToExecutionTarget` becomes a lookup that returns the catalog's exact
   `{ kind: remote, provider: openrouter, model }` target.
4. `executionTargetToUiId` first uses the persisted target ID. Legacy sessions
   may use a catalog reverse lookup. An unknown OpenRouter model gets a stable
   `openrouter:unknown:<digest>` identity and visible slug, never Laguna S.
5. `modelCapabilities` consumes the catalog capability object. UI controls are
   generated only from admitted capabilities.
6. Performance and usage labels fall back to display name/model slug without
   losing `(provider, model)` identity.
7. Settings shows source (`Configured in config.toml`), verification state,
   exact slug, context/modalities, and last metadata observation.

## Request, secrets, and accounting

- Reuse provider `openrouter` and the current secrets-proxy/lease flow. The
  child receives a bounded credential lease, not the long-lived key.
- Continue using the already-authorized project-local `.env` mechanism. Do not
  read, write, import, or prompt for macOS Keychain credentials.
- Pin the configured model slug into the session, run, experiment fact, usage
  record, and recovery projection before the first request.
- Record requested model, provider-reported served model, router attempt/fallback
  metadata when available, token usage, and provider-reported cost.
- Do not add a static tariff for `stealth/ox-alpha` merely because today's
  public listing says zero. For an unversioned/custom model, the UI shows no
  estimate unless an authoritative provider snapshot is retained with its
  effective observation time. Provider-reported settled cost wins. Missing cost
  remains missing, never `$0`.
- Routing preferences are forwarded as OpenRouter provider policy only after
  their current Responses/Chat adapter behavior is covered by tests. Unsupported
  fields fail closed; do not drop them silently.

## Implementation sequence

### C1 — native config and catalog

- Add strict `OpenRouterModelConfig` structs and TOML validation.
- Add catalog command/types and persisted public-metadata snapshot.
- Preserve built-ins through the same catalog representation.
- Add stable target-ID persistence and legacy reverse lookup.

### C2 — dynamic UI

- Replace static OpenRouter arrays/switches in picker, settings, capabilities,
  labels, and session projection.
- Show unverified/unavailable/expired states and useful config diagnostics.
- Keep active historical sessions inspectable after a config entry is removed.

### C3 — request and evidence integrity

- Prove arbitrary slugs reach Codex/OpenRouter unchanged.
- Retain requested/served model and router metadata in usage and experiment
  receipts.
- Ensure unknown pricing is null and provider settlement is authoritative.

### C4 — Ox Alpha acceptance

- Add only the three-line `stealth/ox-alpha` entry to a fresh named v0.8
  instance.
- Refresh metadata, select it in the UI, and run text plus one tool-call turn.
- Remove/disable it, relaunch, and prove the old session still renders with the
  exact model identity while it is absent from new-session choices.

## Tests

### Rust

- minimal TOML entry parses; invalid slug/ID/duplicate/unknown fields diagnose;
- config round-trip preserves unrelated keys and never writes a secret;
- cached metadata starts offline and refresh does not block startup;
- missing/expired models fail closed for new turns;
- arbitrary OpenRouter model survives session/run/event/recovery round-trips;
- unknown model never becomes Laguna S;
- absent price yields no estimate; provider-reported cost settles normally.

### TypeScript/Playwright

- a fixture catalog entry appears in landing, composer, and Settings;
- exact target selection produces `openrouter` + `stealth/ox-alpha`;
- tools/image/reasoning controls follow metadata, not model-name heuristics;
- unverified and unavailable entries cannot make unsupported claims;
- removed entry remains named correctly in a retained transcript;
- no-key state disables send with the existing OpenRouter credential guidance.

### Installed CUA

Use a fresh named v0.8 instance and its own `config.toml`:

1. add the minimal Ox entry and relaunch;
2. verify `Ox Alpha`, `stealth/ox-alpha`, OpenRouter, and verification status;
3. select it and send a nonce-only text request;
4. execute a bounded coding-agent request that makes one harmless workspace
   inspection tool call;
5. inspect the experiment/usage receipt for exact requested and served identity,
   tokens, cost source, and any router fallback;
6. disable the entry and relaunch;
7. verify it is unavailable for a new task but the prior task remains readable;
8. scan logs/receipts for secrets and confirm no Keychain access occurred.

Do not claim the CUA pass if OpenRouter no longer lists or serves Ox Alpha. The
general custom-model feature can still pass using a second currently available
model fixture, while Ox is reported as unavailable rather than silently routed.

## Acceptance criteria

- Adding a new OpenRouter slug requires zero source changes and zero rebuilds.
- The same catalog entry drives picker, settings, capability controls, request
  target, usage, experiments, and recovery.
- Exact provider/model identity survives relaunch, removal, failures, and
  OpenRouter endpoint fallback.
- No silent model fallback, invented capability, guessed price, `$0` for missing
  cost, secret persistence, or Keychain access.
- Invalid config is actionable and cannot erase curated models or corrupt an
  existing session.
- Ox Alpha completes the installed text/tool CUA while it is available.

## Explicitly deferred

- arbitrary OpenAI-compatible base URLs and custom headers;
- in-app editing/installing of custom models;
- automatic import of every OpenRouter model into the picker;
- user-authored tariffs;
- arbitrary generation-body injection;
- cross-model fallback lists and OpenRouter preset authoring.

Those can build on the catalog contract later without weakening the v0.8
identity, security, or accounting rules.
