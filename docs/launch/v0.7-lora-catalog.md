# v0.7 LoRA catalog and dual-family inference

Status: locked 2026-08-20
Parent: [v0.7-optimizers-runtime.md](./v0.7-optimizers-runtime.md)

Every inference-kind LoRA — This Mac (MLX) or hosted SFT/CISPO (Tinker) — is a
catalog row you can list, inspect, rename/tag, archive, and call on **both**
OpenAI families. This is a ship gate for the Optimizers product loop.

## Locked shape

```text
Workshop OptimizerService
  durable runs, local LoRA inventory, union catalog, MCP
        |
        v
Optimizers sidecar
        |
        +-- This Mac  → synth-mlx-rl
        |                 POST /v1/chat/completions
        |                 POST /v1/responses
        |
        +-- Hosted    → public SFT / training service
                          POST /v1/checkpoints/infer/chat/completions
                          POST /v1/checkpoints/infer/responses
                            → Tinker SamplingClient (token in / token out)
```

Rules:

- One catalog noun. Placement is `this_mac` | `hosted`, not a second page.
- Identity is the adapter-tree digest (`sha256:…`). That digest is the mlx-rl
  `policy_snapshot_id`, the eval `artifact_digest`, and the hosted storage hash
  when present. Never key the catalog on a job nickname.
- `OptimizerService` never dials `:8787` or Tinker. The sidecar injects the pin
  and forwards the **native** wire.
- Chat Completions and Responses are peers (mlx-rl D9). Neither family is
  implemented by translating the other.
- Same conversation through either family must render the same transcript
  (one tokenizer, one chat template, one `render_digest`).
- Do not auto-upload MLX adapters into the hosted Wasabi library. Bytes stay
  where they were trained unless the user later hits an explicit Publish.
- A federated object store (one backend for local+hosted bytes) stays out of
  v0.7. The **union catalog view** is in.

## Catalog row

Projection, not the bytes:

| Field | Meaning |
|---|---|
| `checkpointId` | Local: `sha256:<hex>`. Hosted: org checkpoint id. |
| `placement` | `this_mac` \| `hosted` |
| `checkpointKind` | `inference` (chat/eval) \| `training` (resume only) |
| `status` | `writing` → `ready` → `archived` / `bytes_missing` |
| `lineage` | algorithm, base model, step, producing run, parent digest |
| `inference.chat_completions` | capability; hide the action if false |
| `inference.responses` | capability; hide the action if false |

Training-kind rows are resume-only. Chat/Responses only on the inference sibling.

## Live visibility

While a recipe runs, `sft.checkpoint.ready` (and the CISPO equivalent):

1. Appends to the run visual checkpoint rail.
2. Upserts the catalog row (`writing` then `ready`).

Hosted publication into `/api/v1/optimizers/checkpoints` already exists. Local
upserts the Workshop SQLite inventory from sidecar events and terminal handoff.
A run inspector and a catalog card are two views of the same digest.

Orphan `/tmp` adapter trees are invisible until a recipe emits them or the user
**Imports** a validated `mlx-lora.v1` directory.

## Inference (ship gate)

Uniform product paths:

```text
POST {sidecar}/v1/inference/chat/completions
POST {sidecar}/v1/inference/responses
```

Envelope (sidecar-owned; stripped before the origin):

```json
{
  "checkpoint_id": "sha256:… or hosted id",
  "placement": "this_mac",
  "policy_snapshot_id": "sha256:…",
  "adapter_path": "/abs/path",
  "sampler_path": "tinker://…",
  "run_id": "optional",
  "body": { }
}
```

`body` is the native OpenAI family payload. The sidecar injects
`policy_snapshot_id` / `X-Policy-Pin`. Streaming is native per family: This Mac
forwards mlx-rl SSE; hosted Tinker is sampled once, then the HTTP edge emits
family-native SSE. Chat Completions SSE is never translated into Responses
events.

Missing snapshot → 404. Evicted snapshot → 410. **No fallback to the resident
adapter.** Missing family → 501, not a converted request.

### This Mac (synth-mlx-rl)

Origin already serves both families. If the pin is not resident, the sidecar
loads the adapter from `adapter_path` (`POST /v1/checkpoints/load`) and
republishes under `sha256:<tree digest>` before sampling.

### Hosted SFT / CISPO (Tinker)

Tinker’s native API is `SamplingClient.sample(token_ids)`. That is not Chat
Completions or Responses. `/v1/sft/checkpoints/sample` remains a private
messages-only eval helper.

The public SFT/training service owns the D9 facade:

```text
POST /v1/checkpoints/infer/chat/completions
POST /v1/checkpoints/infer/responses
```

One renderer (that checkpoint’s tokenizer + chat template) → token ids →
Tinker sample → family-shaped JSON. `sampler_path` must be `tinker://…`.
If a catalog row has no sampler path, both capabilities are false.

## Eval

Host-owned `eval.*` stays out of the sidecar. Scoring a catalog LoRA means
staging by digest and calling the family the recipe named, with the pin set.
A chat-only Banking77 recipe stays chat; a Responses recipe stays Responses.

## MCP / agent

Same nouns as the page: list/get/archive/import checkpoint, then
`optimizers_checkpoint_infer` with `family=chat_completions|responses`.
The agent never names synth-mlx-rl, `:8787`, or Tinker.

## Not this

- Auto-sync of `/tmp` CISPO trees into Optimizers.
- Wrapping `/v1/training/jobs/{id}/chat` `{message, reply}` as the product API.
- Translating chat ↔ responses on either placement.
- Silent auto-upload of MLX adapters into hosted Wasabi. Bytes stay local until
  the user hits **Publish**. Qwen Optimizers adapters stay off the Laguna
  Composer picker.
