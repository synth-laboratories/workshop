# v0.5 implementation setup

## Branch point

Create `v0.5/implementation` from the reconciled v0.4 release commit after the v0.4 branch has reached `dev`, `main`, and the release tag. Do not branch from the pre-promotion candidate.

## Entry conditions

- v0.4 installed-artifact and paid Banking77 CUA receipts are accepted.
- Workshop, cookbook, frontend, Containers, eval, and testing pins are recorded in the v0.4 release receipts.
- The production download route advertises v0.4 and serves the recorded SHA-256.
- The v0.4 tag is an ancestor of `dev` and `main`.

## Initial v0.5 lanes

1. Replace the friends-only package path with Developer ID signing, notarization, stapling, and notarization receipts.
2. Move the stable release catalog and artifact publication into one atomic, checksum-verified promotion workflow.
3. Turn the Banking77 producer contract tests into shared cookbook conformance fixtures.
4. Eliminate the Rust/Clippy warning backlog and make warnings fatal for changed code.
5. Add an installed-artifact smoke harness that records version, bundle identity, diagnostics, trace navigation, and provider readiness without paid execution.
6. Make full Playwright surface-aware so hidden-surface controls cannot be mistaken for missing data.

## First commands after v0.4 release

```bash
git fetch origin --tags
git switch dev
git pull --ff-only origin dev
git merge-base --is-ancestor v0.4.0 HEAD
git switch -c v0.5/implementation
```

The same branch-point rule applies to the public cookbook and frontend repositories.
