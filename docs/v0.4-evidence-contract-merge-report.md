## Workstream A — GameBench producer contract

`af2fdf5` makes the stream carry what Workshop renders. Before it, a completed
stream held four kinds — `stream.subscribed`, `rollout.progress`, a terminal
`reward_signal` with `payload.reward`, and `eval.run.terminal` — so frames,
policy spans, usage, and action authority were structurally absent.

Now emitted, as the rollout observes them:

- `observation` + `frame` per executed step. Frames are the gold engine's PNG
  for the step that ran, stored before their availability event is visible and
  served from `GET /rollouts/{id}/frames/{step}.png`. A render failure emits
  nothing rather than a reconstructed image.
- `span.policy.opened` → `data` → `plan` → `closed` per model call, carrying
  provider, model, harness/config, the model's own output, selected actions,
  and authority.
- `reward_signal` with canonical `payload.value` as the **reward earned at that
  step**. Accumulating a lane's values reproduces its sealed outcome exactly;
  zero is real evidence, not a placeholder. `reward` survives as an alias of the
  same delta.
- `achievement_unlocked`, `span.step.closed`, `trace.opened`,
  `trace.reconciled` (the Trace V5 link), `eval.run.terminal`.

Action authority is now per-action: `model`, `harness_repair` (the model named a
known verb that was not currently legal), or `harness_fallback` (nothing the
model wrote survived parsing). A harness-chosen action can no longer be reported
as the model's.

Usage is normalized onto the final `span.policy.data` and **omitted** when
unavailable. The Codex subscription lane prices nothing, so it reports nothing.

Three capability-honesty gaps were closed at the same time: `/info` advertised
`reward.get` with no such route (now `GET /rollouts/{id}/reward`); prepare
accepted any `policy_ref` and only rejected it at start, after a stream and
engine session already existed; and poll envelopes carried no top-level rollout
identity, which is what forced ten rollout-local sequences to be disambiguated
downstream. `/info` now also declares `live_frames: "native"`, which is true.

`8796eaa` fixes a defect the live run surfaced: seed resolution was an `or`
chain, so seed 0 fell through to the default on all four paths. A ten-seed
evaluation played seed 1's world twice while still reporting ten distinct
rollout identities and ten distinct Trace V5 records.

Producer contract documented at
`gamebench: tasks/craftax-singleplayer/containers/react/LIVE_EVAL_CONTRACT.md`.

## Workstream B — steering and error presentation

`b6cc7bf`. Two causes, both fixed.

**The gesture failed at human speed.** The first Return queued a prompt and
armed it, but the arm expired on a 2.5s stopwatch — long enough for a synthetic
double press, far too short for a person who must read **Next turns** before
deciding to promote. Once it lapsed the composer's second Return did nothing,
and the only way through was clicking the queued row and pressing Return twice
more. Focusing that row was also load-bearing: its `onBlur` cleared the arm.

Steering is now an explicit state machine in the turn controller
(`runtime/steering.ts`): `idle → armed → promoting → acknowledged | failed`. It
never sees focus, so the second Return promotes identically from the composer or
the queue row. The arm ends on something meaningful — the turn finishing, the
prompt leaving the persisted queue, or new text being typed — and the window
(30s) only bounds a forgotten arm. A prompt leaves **Next turns** solely on
backend acknowledgement, and only the acknowledgement that names it. A reconnect
that replaces the queue disarms rather than steering a prompt that is gone; a
promotion in flight keeps waiting and cannot be delivered twice.

Held Return and IME composition were previously unchecked in the composer at
all: a held key repeated the whole submit path, and an IME commit press was read
as an instruction. Both are handled now.

**Errors leaked internals.** The Rust manager rejects with
`session <uuid> has no active turn to steer`, and the old formatter forwarded
that verbatim, appended the internal code, and fell back to one fixed sentence
for any shape it did not recognize — so a session UUID, a raw transport body, or
a bare object could all reach the composer. Every rejection now maps through
`normalizeSteerFailure` to a stable public code (`steer_turn_finished`,
`steer_unsupported`, `steer_empty`, `steer_unauthorized`, `steer_rejected`,
`steer_unavailable`, also exposed as `data-steer-error-code`), one actionable
sentence, and identifiers redacted. The full structured original stays in
`detail` and in the log. `[object Object]` is not reachable from any shape.

Contract documented at `docs/composer_steering_contract.md`.
