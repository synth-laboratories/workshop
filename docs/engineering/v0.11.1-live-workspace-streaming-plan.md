# Workshop v0.11.1: live workspace streaming plan

Status: final implementation plan
Audience: Workshop desktop, runtime, security, and evaluation engineers
Decision date: 2026-09-14
Target release: **v0.11.1**

## Executive decision

Workshop should add a provider-neutral **live workspace** capability to right-panel visuals. A live visual will be able to show two related but deliberately separate planes:

1. **Evidence plane** — durable, replayable evaluation events and ATIF trajectories, using Workshop's existing cursor/replay contract.
2. **Workspace plane** — an ephemeral, capability-scoped connection to the files and optional editor/terminal of a running sandbox.

Harbor Streams is the first adapter, not the product-level contract. Workshop will reuse Harbor's persisted `StreamHandle`, `EnvironmentFactory.connect_ssh`, and provider lifecycle instead of reimplementing Daytona or Docker SSH behavior. A native read-only file explorer is the portable baseline. Harbor's browser VS Code experience is an optional richer capability served through a Workshop-owned, fixed-origin loopback gateway.

The target is **Workshop v0.11.1**. This is a patch release because the feature is additive, existing `live.harbor_eval.v1` visuals remain readable, existing bindings remain valid, and no public behavior must be removed or changed incompatibly. The requested version policy changes only the `y` component of `v0.x.y`, taking `v0.11.0` to `v0.11.1`.

## What Harbor actually shipped

Harbor proposed the implementation in PR #3171. As verified on September 14, 2026, the PR remains unmerged: its exact head is `d4fe6133eb196247cad104d01103e37f67ec488d`, while Harbor `main` is `26f5d8f423786d55a25c5ef4f0eb5869e93ad2df`. The matching documentation is PR #3172 at `7874b15eeb9dc6054032ccca915d208c4699f5f2`.[^1] [^2] Both the installed CLI and the PR package metadata report 0.22.0, but released 0.22.0 does **not** contain the feature. Workshop therefore treats the feature as an experimental compatibility target and pins the exact PR head rather than installing a floating branch.[^3]

The user flow is:

```bash
harbor run -t terminal-bench/build-cython-ext \
  -a claude-code -m anthropic/claude-sonnet-5 -e docker --stream
harbor view jobs
```

The viewer provides a live trajectory and an embedded code-server workspace. Harbor currently documents the combination for Claude Code and Codex agents on local Docker and Daytona environments. `--no-delete` is required if the user must reconnect after a run completes; otherwise sandbox deletion makes the workspace unavailable. The runner and viewer must be on the same machine, and Daytona credentials must be available to both processes.[^2]

### Upstream architecture and behavior

| Area | Harbor implementation | Consequence for Workshop |
|---|---|---|
| Capability | `EnvironmentCapabilities.stream` and `EnvironmentConfig.stream`; unsupported environments fail before the job starts | Discover capability before exposing Workspace UI; never guess support from an environment name |
| Persisted handle | `trial_dir/stream.json` contains provider, opaque reference, and optional absolute workspace; credentials are acquired independently | Store an opaque descriptor, never credentials, in a visual binding |
| Reconnection | `EnvironmentFactory.connect_ssh(handle)` reconnects without reprovisioning the trial | Call Harbor's adapter rather than duplicating provider authentication and lease behavior |
| Docker | Named local Docker contexts only; remote `DOCKER_HOST` is rejected; SSH is loopback-only with host-key pinning and generated ED25519 keys | Treat remote Docker as unsupported initially; keep the private identity host-side |
| Daytona | Handle stores sandbox ID; credentials resolve on attach; temporary SSH access is revoked on exit, cancellation, or error | Let Harbor own Daytona access leases and cleanup |
| Trajectory preview | Every two seconds, native session JSONL is copied over SSH, safely extracted, converted using the agent's existing converter, and atomically written as `trajectory.json` | Consume ATIF preview as provisional evidence and reconcile with the authoritative final trajectory |
| Editor | code-server 4.133.0 is downloaded for amd64/arm64, SHA-256 checked, started on remote loopback, and forwarded to a dynamic local port | Proxy HTTP and WebSockets through one Workshop origin; first attach may take minutes or fail without egress |
| Limits | Four simultaneous editors; five-minute idle timeout; 30-second reaper | Match or tighten these defaults and expose clear capacity/idle states |
| Security | Viewer stream endpoints are loopback-client-only; errors are sanitized; iframe is sandboxed; code-server itself uses `auth none` behind the SSH tunnel | Never expose the forwarded code-server port directly or treat an unguessable URL as authentication |

Harbor's trajectory preview is robust against partially written logs: it writes a temporary result and atomically renames it, preserving the last good preview on transient errors. The output is ATIF, Harbor's standardized agent-trajectory representation.[^4] However, it recopies native logs on the polling interval rather than maintaining a byte-offset incremental transport. Large sessions may therefore consume increasing bandwidth and CPU. Workshop should preserve Harbor behavior in the adapter but use cursor-based incremental events for its own native stream contract.

Harbor's full editor is intentionally mutable. A user can edit files or run terminal commands while the agent is executing. That is valuable for debugging, but it changes evaluation state and can invalidate an official score. Workshop must not present mutable access as passive observation.

## Current Workshop foundation

Workshop already has most of the evidence plane:

- `synth.visual-bindings.v1` declares input sources and canonicalizes their identities.
- `live_sse` bindings declare poll and optional SSE endpoints; the host allowlists only those declared endpoints.
- The replay client treats durable polling as authoritative and SSE as an optional latency optimization.
- `liveStream.ts` tracks cursor high-water marks, gaps, conflicts, closure, logical time, and control envelopes.
- `harborEval.ts` projects Harbor attempts without fabricating missing rewards.
- Stream receipts record transport behavior with bounded evidence retention.
- `VisualHost.tsx` constructs clients from host-resolved bindings rather than allowing arbitrary visual network access.
- Container capability discovery already provides a pattern for explicit operations and capabilities.

The missing element is a workspace transport and UI. The current `live.harbor_eval.v1` template is event-only. The current managed HTML frame is designed for reviewed, immutable `srcDoc` renderers and is not suitable for code-server, which requires same-origin behavior, WebSockets, and service-worker-compatible loading. The desktop CSP also permits frames only from `self` and `http://127.0.0.1:7338`; Harbor's random forwarded ports cannot be safely embedded as-is.

## Product contract

### Binding

Add a new optional `live_workspace` binding kind. Keep the event and workspace inputs independent:

```json
{
  "schemaVersion": "synth.visual-bindings.v1",
  "inputs": [
    {
      "input": "stream",
      "kind": "live_sse",
      "source": "run:01J...",
      "poll_url": "http://127.0.0.1:7338/streams/01J.../poll"
    },
    {
      "input": "workspace",
      "kind": "live_workspace",
      "source": "workspace-descriptor:01J..."
    }
  ]
}
```

The visual record references a durable descriptor, not a live socket, transient forwarded port, credential, SSH key, or public tunnel URL. On reopen, the host attempts a fresh attach. If the sandbox is gone, the visual continues to render durable trajectory and artifacts and reports the workspace as expired.

### Descriptor

Introduce `synth.live-workspace.v1`:

```json
{
  "schemaVersion": "synth.live-workspace.v1",
  "id": "01J...",
  "provider": "harbor",
  "reference": { "trialPath": "/absolute/path/to/trial" },
  "workspace": "/workspace",
  "runId": "01J...",
  "trialId": "trial-name",
  "requestedCapabilities": ["files.read", "files.watch", "trajectory.preview"],
  "mode": "observe",
  "retention": "sandbox_lifetime"
}
```

Rules:

- `provider` selects a host-side adapter; renderers cannot register adapters.
- `reference` is provider-specific but schema-validated and bounded.
- `workspace` must be absolute where the provider requires it.
- credentials and bearer URLs are forbidden fields and rejected during admission.
- `mode` defaults to `observe`; `interactive` requires explicit user action.
- requested capabilities are an upper bound. The actual attached session may grant fewer.

### Capabilities

Use granular capabilities rather than a single `stream: true` flag:

- `files.read`
- `files.watch`
- `editor.view`
- `files.write`
- `terminal`
- `port.forward`
- `snapshots.create`
- `trajectory.preview`
- `artifacts.read`

The initial portable baseline is `files.read`, `files.watch`, `trajectory.preview`, and `artifacts.read`. Harbor may additionally offer `editor.view`; mutation-related capabilities are disabled by default.

### State machine

Workspace state is distinct from run state:

```text
unavailable -> disconnected -> connecting -> observing
                                      |          |
                                      v          v
                                    failed   interactive
                                                 |
                                                 v
                                               stale

observing/interactive/stale -> disconnected | expired
```

`terminal` is a run lifecycle state, not a workspace state. A completed run can retain an observable workspace when Harbor used `--no-delete`, while a running job can lose its workspace connection. The UI must not conflate these conditions.

## Host architecture

Define a Rust-side provider interface conceptually equivalent to:

```rust
trait LiveWorkspaceProvider {
    fn validate(&self, descriptor: &Descriptor) -> Result<()>;
    async fn attach(&self, descriptor: &Descriptor) -> Result<AttachedSession>;
    async fn capabilities(&self, session: &AttachedSession) -> Result<Capabilities>;
    async fn list(&self, session: &AttachedSession, path: &SafePath) -> Result<Vec<Entry>>;
    async fn read(&self, session: &AttachedSession, path: &SafePath, range: Range) -> Result<Bytes>;
    async fn watch(&self, session: &AttachedSession, cursor: Cursor) -> Result<Page<FileEvent>>;
    async fn open_editor(&self, session: &AttachedSession) -> Result<EditorRoute>;
    async fn detach(&self, session: AttachedSession) -> Result<()>;
    async fn health(&self, session: &AttachedSession) -> Health;
}
```

All provider interaction occurs outside the visual renderer. The renderer receives typed, bounded results through the generated desktop contract.

### Harbor adapter

The Harbor adapter is a small pinned Python helper/sidecar invoked by Workshop. It should:

1. Load and validate the selected trial's `stream.json` using the pinned Harbor package.
2. Call `EnvironmentFactory.connect_ssh(StreamHandle)` to acquire provider-specific access.
3. Use Harbor's `StreamManager` for code-server lifecycle where editor capability is requested.
4. Return only sanitized session metadata to Rust.
5. Keep leases, SSH processes, and cleanup inside the helper's lifecycle.

Do not translate the handle into a homemade Docker or Daytona login. That would duplicate upstream security logic, diverge when Harbor adds providers, and risk leaking temporary credentials.

Pin `d4fe6133eb196247cad104d01103e37f67ec488d` in the development integration. Add a compatibility test that reads the current `StreamHandle` schema and attaches to local Docker. Move to the merge commit, and later the first semver Harbor release containing PR #3171, only after that test passes; record the resolved Harbor version/commit in every workspace receipt.

### Other adapters

- **Local Docker:** use the Docker Engine API or CLI against an explicitly selected local context; expose the native read-only file protocol first. Do not silently add SSH to arbitrary containers.[^7]
- **Generic SSH:** require an operator-declared host, root path, and identity reference. Enforce host-key verification and `BatchMode`; do not accept renderer-provided command-line fragments.
- **Kubernetes:** later adapter using authenticated API access and port-forward semantics. Namespace, pod, container, and root must be explicit.[^8]
- **Daytona:** continue through Harbor first. A native adapter is justified only if Workshop needs non-Harbor Daytona sessions.
- **Modal:** use sandbox APIs for lifecycle. Modal tunnels are public endpoints even when their URLs are cryptographically random, so Workshop must place an authenticated local proxy in front and must never persist or embed the tunnel URL as a bearer secret.[^9] [^10]
- **HTTP-only containers:** remain evidence/artifact-only. The absence of a workspace capability is a supported state, not an error.

### Fixed-origin loopback gateway

Create one Workshop-owned gateway on a stable loopback origin. It multiplexes sessions under capability-scoped paths:

```text
http://127.0.0.1:7338/live-workspaces/<session-token>/...
```

This gateway terminates renderer access, validates every request, and reverse-proxies HTTP and WebSockets to the provider's dynamic local endpoint. It permits a narrow CSP (`frame-src` for the existing Workshop loopback origin) without allowing every random localhost port. code-server's own guidance warns against direct unauthenticated exposure and requires WebSocket-capable proxying.[^5] [^6]

Requirements:

- unguessable, per-session token scoped to one visual and capability set;
- `Host`, `Origin`, and token validation on HTTP and WebSocket upgrades;
- no provider credential, SSH key, upstream URL, or raw error returned to the renderer;
- request, response, file-size, and concurrency bounds;
- idle expiration, explicit disconnect, application-exit cleanup, and crash recovery;
- no arbitrary forward proxy behavior;
- audit receipt for attach, detach, capability grants, interventions, and failures.

## Right-panel experience

Release `live.harbor_eval.v2` while keeping `v1` registered for existing visuals. The right panel contains:

- **Overview** — run identity, model, environment, status, reward, verifier, and workspace availability.
- **Trajectory** — partial ATIF actions while running, clearly marked provisional; reconciled final trace after completion.
- **Workspace** — provider-neutral file tree and file preview. When `editor.view` is available, an “Open editor” affordance loads the proxied code-server frame.
- **Artifacts** — durable outputs and snapshots.
- **Terminal** — absent unless the user explicitly enters interactive mode and the provider grants it.

The panel should open as soon as the visual is selected or created; it must not wait for the first trajectory event. `stream.subscribed` is readiness, not evidence. Empty, connecting, stale, expired, and failed states need distinct messages and recovery actions.

Recommended live layout:

```text
+-------------------------------------------------------+
| Live • Craftax / trial 3          Observe | Reconnect |
+--------------------------+----------------------------+
| Trajectory               | Workspace                  |
| provisional action feed  | files / preview / editor   |
| cursor, gaps, status     | provider + connection      |
+--------------------------+----------------------------+
| reward / verifier / artifacts / intervention status   |
+-------------------------------------------------------+
```

Craftax and other visual environments may render frames from normal event/artifact inputs beside the workspace. Banking77 remains primarily trajectory/metrics-oriented but can still expose generated files when the harness supplies a workspace descriptor. The visual family must degrade cleanly when only the evidence plane exists.

## Evaluation integrity and security

Observation is the default. Native file reads must be rooted to the declared workspace, resolve canonical targets, reject traversal, and prevent symlink escape. Apply binary detection, range reads, and size ceilings. Renderer code cannot select an arbitrary host path.

Enabling `files.write`, `terminal`, or unrestricted editor behavior starts an intervention:

```text
operator.intervention.started
operator.intervention.action
operator.intervention.ended
```

The UI displays a persistent “Interactive — evaluation modified” banner. The verifier result and report carry the intervention receipt, and policy decides whether the score is invalid, unofficial, or merely annotated. Workshop must never claim that a mutated run is an untouched benchmark result.

For code-server, disable extensions, telemetry, update checks, port exposure, and downloads where practical in observe mode. If upstream code-server cannot provide truly read-only semantics, label it interactive and use the native file explorer for read-only observation.

Credentials remain host-side. Follow Workshop's existing credential policy: project-local `.env` files and the authorized secrets proxy are preferred; do not access macOS Keychain or the Keychain-backed Secrets registry unless the user explicitly authorizes that specific operation. A workspace descriptor must remain safe to persist and share without credentials.

## Implementation sequence

### PR 1 — contracts, storage, and receipts

- Add `live_workspace` to the binding model and canonicalization.
- Add `synth.live-workspace.v1`, granular capabilities, and lifecycle enums.
- Add migration-backed descriptor/session/receipt storage; persist descriptors and receipts, not active credentials.
- Extend generated desktop contracts with attach, capabilities, list, read, watch, editor route, health, and detach operations.
- Add admission checks rejecting secret-looking fields, URLs in disallowed fields, oversized references, and invalid paths.

Primary areas: `apps/synth_desktop/src-tauri/src/visuals`, `storage/migrations.rs`, `contract/desktop_dispatch.rs`, generated tools, and `desktopBridge.ts`.

### PR 2 — host gateway and native read-only workspace

- Implement session manager, fixed-origin gateway, HTTP/WS authorization, idle reaper, and cleanup.
- Implement provider-neutral list/read/watch APIs and the native file tree/preview UI.
- Bound sessions to four initially, five-minute idle timeout, 30-second cleanup cadence.
- Add receipts and metrics for connection latency, bytes, reconnects, and sanitized failures.

### PR 3 — Harbor adapter

- Pin the exact Harbor implementation commit.
- Add helper lifecycle and schema compatibility tests.
- Attach local Docker through Harbor's persisted handle.
- Integrate provisional ATIF preview and authoritative final reconciliation.
- Integrate code-server through the fixed-origin gateway, including WebSockets.
- Detect missing egress/code-server installation separately from SSH/workspace failure.

### PR 4 — visual family and controller integration

- Register `live.harbor_eval.v2`; retain `v1`.
- Add Overview, Trajectory, Workspace, and Artifacts tabs.
- Auto-open the right panel on visual open/create and preserve selected subtab.
- Add reconnect, stale, expired, and partial-capability UX.
- Add intervention mode and score-validity annotation.
- Make Craftax live frames and workspace updates coexist; validate Banking77's evidence-only and workspace-capable variants.

### PR 5 — generic container adapters and hardening

- Add local Docker read-only adapter independent of Harbor.
- Add generic SSH only after threat-model review.
- Exercise Kubernetes and Modal prototypes behind feature flags; do not hold v0.11.1 for them.
- Add load, failure-injection, crash recovery, and packaging coverage.

PRs 1–4 are required for v0.11.1. PR 5's Docker baseline is desirable but not release-blocking if Harbor local Docker and the provider-neutral contract are proven.

## Verification plan

### Unit and contract tests

- Accept valid descriptors and reject credentials, bearer URLs, traversal, symlink escape, malformed provider references, and unsupported schema versions.
- Prove binding canonicalization remains stable for every existing kind.
- Prove `live.harbor_eval.v1` fixtures still render unchanged.
- Parse a fixture produced by Harbor commit `3d591a...`; unknown providers fail closed with a useful message.
- Verify session token, `Host`, `Origin`, method, path, and WebSocket upgrade enforcement.
- Verify file/range limits, binary handling, cursor deduplication, gaps, and bounded receipts.
- Verify idle timeout, maximum sessions, cancellation, detach, process exit, and orphan cleanup.
- Verify partial ATIF never replaces the last good preview and final ATIF becomes authoritative.

### Component and desktop tests

- Opening a live visual opens the right panel before the first event.
- Workspace tab appears only for an admitted descriptor; missing capability degrades to trajectory/artifacts.
- A file created in a sandbox appears live and can be previewed read-only.
- Observe mode has no edit or terminal affordance.
- Entering interactive mode emits intervention receipts and changes the validity banner.
- App restart reattaches when the sandbox exists; sandbox deletion produces “Expired” while durable evidence still renders.
- The code-server frame loads scripts, service workers, and WebSockets only through the fixed gateway origin.
- Two to four sessions work concurrently; a fifth gets a bounded capacity message and retry action.

### End-to-end matrix

| Scenario | Evidence | Workspace | Required result |
|---|---|---|---|
| Harbor + Codex + local Docker + Craftax | live and final ATIF, frames, reward | files and optional editor | Right panel updates during play; final reward remains honest |
| Harbor + Codex + local Docker + Banking77 | live and final ATIF, metrics | generated files if declared | No visual blank state; workspace optional |
| Harbor completed with `--no-delete` | sealed evidence | reconnectable | Reopen succeeds after run completion |
| Harbor completed without retention | sealed evidence | expired | Visual remains useful and explains expiration |
| Harbor + Daytona | live/final | files/editor | Credential-gated test; temporary lease revoked on detach |
| Generic local Docker | native events/artifacts | read-only files | Works without Harbor-specific UI |
| HTTP-only runner | native events/artifacts | unavailable | Clean evidence-only degradation |
| No egress for code-server install | trajectory works | native files work, editor unavailable | Partial capability, actionable message |
| Large trajectory and binary/large files | cursor stream stays bounded | range/binary policies enforced | Responsive UI and bounded memory/disk |
| Crash/restart | durable replay recovers | fresh attach or expired | No leaked child process or stale credential |

The Harbor paid-provider smoke should use Luna or Gemini 2.5 Flash Lite throughput routing, following the existing exact-model fallback policy. It requires a fresh bounded cost statement before execution because prior experiment authorization is not implicitly reusable. Most protocol, lifecycle, and UI tests should use deterministic fixtures and local containers and incur no provider cost.

### CUA acceptance script

1. Start Workshop v0.11.1 and a Harbor local-Docker Craftax stream.
2. Open the resulting visual and confirm the right panel opens immediately.
3. Confirm live trajectory events and Craftax frames arrive without manual refresh.
4. Open Workspace, watch a created file appear, and preview it.
5. Confirm terminal and mutation controls are absent in observe mode.
6. Reconnect after closing/reopening the panel.
7. Complete the run; confirm final reward/verifier and sealed trajectory reconcile without fabricated data.
8. Restart Workshop and reopen the visual with and without a retained sandbox.
9. Repeat an evidence-only Banking77 run and confirm graceful absence of workspace controls.
10. Exercise Settings, capability denial, stale connection, code-server installation failure, and session-capacity states.

Release performance targets:

- visible live update within three seconds under normal local conditions, matching Harbor's two-second trajectory cadence;
- responsive scrolling and selection at 100,000 evidence envelopes;
- bounded receipt, file preview, proxy buffer, and disk usage;
- no renderer access to arbitrary loopback ports or filesystem paths;
- no leaked SSH, code-server, helper, or proxy process after detach/app exit.

## Explicit non-goals for v0.11.1

- Supporting every Harbor environment; only environments declaring stream capability qualify.
- Making code-server the universal workspace protocol.
- Exposing arbitrary container ports to visual code.
- Persisting a live editor as evidence.
- Silently mutating official evals.
- Replacing Workshop's cursor/replay evidence protocol with Harbor's log-copy loop.
- Shipping native Kubernetes, Modal, or every SSH provider before the Harbor and local-Docker paths are sound.

## Definition of done

v0.11.1 is complete when a Workshop user can launch or attach to a supported Harbor evaluation, open its visual in the right panel, observe live trajectory and workspace changes without permission churn, optionally enter a clearly audited interactive mode, recover or understand connection loss, and reopen the durable result after the sandbox disappears. The same UI must degrade correctly for non-Harbor and evidence-only runs. Provider credentials stay host-side, visual records remain safe to persist, evaluation integrity is explicit, and all release gates above are backed by automated receipts and an end-to-end CUA run.
